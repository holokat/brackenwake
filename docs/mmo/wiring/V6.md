# V6: arbor.js, the Arbor Forest Studio engine as a game module

Files owned and written: `src/world/arbor.js`, `src/world/arbor_textures.js`,
`src/world/arbor.test.mjs`, this document. Nothing else was touched, and
nothing else in `src/` imports arbor yet, so merging it is additive.

`docs/reference/arbor-forest-studio.jsx` is the source. Trees are grown, not
modelled: an axis is a tapered tube of rings, it spawns an apical continuation
and a whorl or spiral of laterals, and the last order of every axis sprays leaf
quads along itself. The reference's numbers are kept; the four extra species,
the biome mixes, the wind field and the `detail` lever are additions, and each
one is called out below.

Run `node src/world/arbor.test.mjs`. 133 checks, all green. Every number in
this document came out of that run, not out of an estimate.

---

## 1. The API

```js
import * as arbor from './arbor.js';
```

### Species

`arbor.SPECIES` is a table of eleven, `arbor.SPECIES_IDS` their ids.

| id | source | note |
| --- | --- | --- |
| oak, beech, birch, spruce, pine, kapok, fig | the reference, verbatim | |
| willow | new | gravity 1.6, tropism -0.22: the bole climbs, the whips fall |
| palm | new | levels 1, habit `palm`, `bole` 0.92: one trunk, seven fronds |
| sakura | new | spreading, `leaf: 'blossom'`, its own autumn colours |
| dead | new | `leaf: null`, `leafPer: 0`, grey `#8d8880` bark |

Two parameters are new and only the new species use them:

- `habit: 'palm'`, which puts every lateral at the top of the trunk instead of
  spreading them up it.
- `bole`, the first axis length as a fraction of the nominal height. It
  defaults to the reference's 0.34 (conical) and 0.4 (everything else). Only
  palm sets it. It exists because the reference's 0.4 assumes a chain of apical
  continuations stacks the rest of the height out, and a `levels: 1` tree has
  no such chain: palm's mesh reached 5.1 m when its parameters said 11.2 m.
  The test now checks every species reaches 60% of its nominal height in real
  vertices, so a twelfth species cannot ship with the same hole.

### Forest types

`arbor.FOREST_TYPES` holds the reference's five under their own names, plus one
per game biome. Each carries `mix`, `ground[3]`, `grass[2]`, `relief`, `fog`,
`sky[2]`, `under` and a default `density`.

| id | mix | source |
| --- | --- | --- |
| Temperate broadleaf, Boreal conifer, Tropical wet, Birch grove, Mediterranean pine | | the reference, verbatim |
| meadow | oak .45, beech .35, birch .2 | Temperate broadleaf, aliased |
| boreal | spruce .6, pine .25, birch .15 | Boreal conifer, aliased |
| mountain | pine .7, oak .3, `thinByHeight: [46, 78]` | Mediterranean pine, aliased, plus thinning |
| sakura | sakura .5, birch .4, oak .1 | new: a Birch grove with cherry through it, keeping the grove's floor and air |
| desert | dead .75, palm .25; `wetMix` palm .85, dead .15 | new |
| snow | spruce 1.0 | new |
| beach | palm .85, dead .15 | new. Not on the brief, but field.js has eight biomes and one case is never the case |
| ocean | empty | new. `placeTrees` returns `[]`, `grassChunk` returns `null` |

`arbor.canonicalType(id)` returns `alias || id`. **Key your prototype cache on
it.** `meadow` and `Temperate broadleaf` are the same forest under two names,
and building both would grow and hold two identical 7.5 MB stands.

`arbor.auditForestTypes()` runs at import and throws on a mix naming a species
that does not exist, a mix that does not sum to 1, a game biome with no forest
type, a leaf kind or bark style with no recipe, or an unknown habit. The test
drives it in both directions: clean on the shipped tables, throwing on three
deliberate breaks.

### Growing a tree

```js
const p = arbor.buildPrototype('oak', seed, opts);   // raw, uncached
const p = arbor.prototypeFor('oak', seed, opts);     // memoised on all three
const stand = arbor.forestPrototypes('meadow', field.seed, opts);  // 8 of them
```

`opts` is the studio's seven sliders with the studio's defaults, plus `detail`:

```
heightScale 1.0   crownSpread 50   trunkRadius 1.0   maturity 0.75
gnarl 0.35        foliage 1.0      autumn 0         detail 1.0
```

Returns:

```js
{
  bark, leaf,          // BufferGeometry, foot at the origin, +y up, unscaled
  barkMat,             // MeshStandardMaterial, bark map plus normal map
  leafMat,             // alphaTest 0.45, DoubleSide, vertexColors, wind hooked
  depthMat,            // set as customDepthMaterial so shadows are cut out too
  height,              // metres MEASURED off the tallest bark vertex
  grownHeight,         // metres the parameters asked for (inside SPECIES.h)
  radius,              // trunk radius at the base, metres
  crownRadius,         // widest xz reach of bark or leaves, metres
  hasLeaves,           // false for `dead` and for foliage 0: build no leaf mesh
  species, seed, detail, triangles, axes,
}
```

`forestPrototypes` is the reference's `rebuild()` loop exactly: one rng draws
both the species from the mix and each tree's maturity, so a stand carries
saplings and old growth. Measured: eight distinct heights out of eight draws.

### Placing them

```js
const spots = arbor.placeTrees(typeId, cx, cz, 64, field.seed, opts);
// -> [{ x, z, scale, yScale, yaw, protoIndex }]
```

Pure. No THREE, no scene, no field. The jittered grid, the four rolls per cell,
their order, the fbm thinning and the three densities are the reference's:
`spacingFor` gives 21 / 13 / 8 and `thresholdFor` gives 0.44 / 0.34 / 0.24 for
Open / Natural / Dense.

`opts`: `density`, `protoCount` (8), `clearRadius` (0), `heightAt`, `keep`,
`spacing`, `threshold`, `wet`.

Three things worth knowing:

- **Every roll is drawn before any rejection.** That is the reference's order
  and it is load bearing: a clearing is then a hole in the forest rather than a
  different forest. Verified by asserting `placeTrees(..., {clearRadius: 40})`
  is byte for byte the filter of the unclipped list.
- **`clearRadius` defaults to 0, not the reference's 9.** The studio kept 9 m
  clear around its camera. The game has `flora.js HOME_CLEAR = 125` for that,
  and a hard 9 m hole at the world origin would be a bug nobody asked for.
- **A tree can land up to `spacing * 0.45` outside its own chunk** (up to 5.8 m
  at Natural). Assign it to the chunk that generated it, as flora.js already
  does with `chunk: chunkKey`, never by position.

`thinByHeight` costs one extra rng draw per cell and is only drawn when the
type has one AND `heightAt` was passed, so a type without it places exactly as
the reference does. Measured on mountain over a 64 m chunk at Natural:

```
0 m 25   20 m 25   46 m 25   55 m 20   62 m 15   70 m 6   78 m 0   90 m 0
```

Full below the rock line, monotone through the middle, bare at the snow line.

### Grass and ground

```js
const { geo, mat } = arbor.buildGrassAssets();          // three quads, 18 tris
const im = arbor.grassChunk('meadow', gx, gz, { heightAt, seed, grass, size, keep });
const groundMat = arbor.groundMaterial(96);
```

The blade cross and the `GC * GC * 7 * grass * under` count are the reference's.
The one change: the reference read its own terrain function for the blade
height, and `grassChunk` takes `heightAt` instead so the game's field decides.
`keep(x, z)` is the caller's veto, for roads, rivers and the home clearing.
Returns `null` rather than an empty mesh when the count works out at zero.

## 2. Varying wind

**The wind field is a world-space term inside the shader, not a per chunk
uniform.** That is the answer to "say in V6.md which you did".

`windUniforms` stays shared by every material the module makes, exactly as the
reference had it: `uTime` and `uWind`. What changed is that `uWind` is now a
BASE. The vertex shader evaluates two slow sine swells at the vertex's own
world position and modulates the base by them, so one draw call covers a whole
forest and the far side of it still sways differently from the near side. No
material cloning, no extra shader programs, no extra draw calls.

`windField(x, z, t, base)` is the same expression in JS, transcribed line for
line, and is the function to call for anything gameplay side: a falling leaf
effect, wind audio, a sail.

```js
const { strength, angle, dirX, dirZ } = arbor.windField(x, z, nowS);
```

Measured over 22 million square metres and 600 seconds of clock, at base 1:

- strength lands in `[0.350, 1.649]`, inside the `[0.35, 1.65] x base` the
  construction guarantees. Never a NaN.
- direction stays within 0.55 rad of `PREVAILING` (pi/4): 14 to 76 degrees.
- two stands 2 km apart read 1.18 and 0.51. Two trees 6 m apart read 1.182 and
  1.194, so a single tree does not shear.
- base 0 stills the whole field exactly.

`setWindVariation(false)` reverts the hook to the reference's flat wind, which
is the escape hatch if the gust reads wrong on screen. The test drives both.

Two other departures in `windHook`, both fixes rather than taste:

- the `instanceMatrix` read is wrapped in `#ifdef USE_INSTANCING`, so the hook
  cannot break a plain mesh (the reference would have thrown at compile).
- amplitudes are emitted through `toFixed(4)`, so an integer amp cannot become
  an invalid GLSL float literal.

The direction rotation means the leaf displacement is `amp * 1.25` along a unit
vector rather than the reference's fixed `(1.0, 0.75)` split; at the prevailing
angle those are within 12% of each other in magnitude. Grass is `0.45` along
the same unit vector against the reference's `(0.32, 0.2)`.

### What to tick

One call per frame, in `main.js` or `world_runtime.js`, seconds not milliseconds:

```js
arbor.tick(performance.now() / 1000);
```

`arbor.setWind(s)` sets the base. Nothing else needs driving. If weather ever
arrives, `setWind` is the one hook it should pull.

## 3. How flora.js should call this

flora.js keeps ONE `TreeField` per kind for the whole world and rebuilds its
instanced meshes from plain records. That contract does not need to change; the
kinds do. Instead of `kinds.oak` being a trunk cylinder and three sphere
canopies, one kind becomes **one prototype**, with two layers.

```js
// once, lazily, for each forest type actually streamed
const key = arbor.canonicalType(biomeId);
const stand = standCache.get(key) || standCache.set(key,
  arbor.forestPrototypes(key, field.seed, { detail })).get(key);

// one TreeField per (forest type, prototype index): 13 types x 8 is the cap,
// but only the types actually on screen are ever built
function fieldFor(key, i) {
  const proto = standCache.get(key)[i];
  return createTreeField({
    name: `arbor:${key}:${i}`, kind: 'tree', parent: group,
    layers: [
      { geo: proto.bark, mat: proto.barkMat,
        of: (t) => ({ x: t.x, y: t.gy, z: t.z, s: t.s, sy: t.sy, ry: t.ry }) },
      ...(proto.hasLeaves ? [{
        geo: proto.leaf, mat: proto.leafMat,
        tag: (im) => { im.customDepthMaterial = proto.depthMat; im.userData.foliage = null; },
        of: (t) => ({ x: t.x, y: t.gy, z: t.z, s: t.s, sy: t.sy, ry: t.ry }),
      }] : []),
    ],
  });
}
```

Four things to get right, each of which will otherwise ship as a silent bug:

1. **The prototype geometry has its foot at the origin and is unscaled.** Both
   layers take the SAME transform. There is no per part `y` offset any more,
   which is what the old kind layouts were full of. Pass `y: t.gy` for both.
2. **`hasLeaves` false means build no leaf layer at all.** `dead` has an empty
   leaf geometry, and `foliage: 0` empties any species. An `InstancedMesh` on a
   zero vertex geometry draws nothing but still costs a draw call and a
   bounding sphere of NaN.
3. **`customDepthMaterial` has to be set through the layer's `tag` hook.**
   `tree_edit.js` calls `layer.tag(im)` on the built InstancedMesh, which is
   the only place to reach it. Without it the canopy casts a solid box shadow
   instead of a cut out one.
4. **The seasonal recolour in farm.js tags `im.userData.foliage` with a hex and
   tints the material.** Arbor leaves carry their colour in vertex attributes,
   not in `material.color`, so that pass will do nothing to them. Either leave
   `foliage` unset (autumn then comes from `buildPrototype({ autumn })`, which
   is the better answer since it recolours per leaf) or teach the season pass
   to rebuild the stand at a new `autumn` value. Do not tag them and assume it
   worked.

The record contract for `chopTree` is untouched: records still carry
`{ x, z, gy, s, sy, ry, alt, oa, chunk }`, `felledUntil` still hides an
instance, `userData.treeMap` still maps a raycast hit back to a record.
`proto.crownRadius` and `proto.height` are there for the felling animation and
for a pick radius, both measured off the vertices rather than assumed.

Placement can stay flora.js's own per 8 m cell roll, or switch to `placeTrees`.
Switching changes the stand density: flora.js's `DENSITY.meadow.oak = 0.16`
over 64 cells is about 10 trees per chunk, and arbor's meadow at Natural is
20.5. Boreal goes from about 35 to 62. If flora.js keeps its own placement, it
still needs a `protoIndex` per record; `hash2(gx, gz, seed) % 8` will do.

### Draw calls

**16 per forest type, for the whole world**, if flora.js keeps one InstancedMesh
per (prototype, part) globally, which its one field per kind design already
does. Not 16 per chunk. Chunks add and remove records; the meshes are rebuilt,
not multiplied.

Realistically two or three biomes are in view at once, so 32 to 48 draw calls
for every tree on screen, plus one per grass chunk. Worst case if every one of
the thirteen types were resident at once is 208, which is why `canonicalType`
exists: it collapses the three aliased pairs and takes the real cap to 20 sets.

### Triangles drawn, per 64 m chunk, at each type's default density

```
meadow   detail 1    347,273      detail 0.5   194,618
boreal   detail 1    931,576      detail 0.5   503,812
mountain detail 1     64,922
```

**Boreal at Dense is the problem, and it is a real one.** A 5 x 5 ring of
loaded chunks would be 23 million triangles a frame. Three ways out, in the
order I would try them:

1. **`detail` past the first ring.** It is the only lever this module adds that
   the reference does not have: it scales the ring segment count and the leaves
   per node, and at 1.0 it is exactly the reference. Measured on one boreal
   chunk: 978,626 / 725,608 / 526,304 / 435,342 triangles at detail 1 / 0.7 /
   0.5 / 0.35. Half the detail is 54% of the cost. It needs a second prototype
   set per type, which doubles the 7.5 MB, so build it only for the types that
   are actually resident.
2. **Drop boreal to Natural.** 62 trees per chunk is the reference's Dense over
   a 64 m chunk rather than its own 96 m one, and 20.5 reads as forest already.
3. **A shorter tree ring.** flora.js already gates trees on `TREE_TIER` verts.

I did not choose for you: the choice is a look decision and it belongs with
whoever is holding the camera. What I can say is that the numbers above are
measured, and that a Natural meadow chunk at detail 0.5 comes to 194,618
triangles, which is a budget the game can carry.

### Grass

One `InstancedMesh` per 24 m chunk, 4,032 blades at meadow's `under: 1.0`,
18 triangles each, so 72,576 triangles and one draw call per chunk. The
reference streamed a 5 x 5 ring of those, which is 1.8 million triangles and 25
draw calls. flora.js's `GRASS_RING` currently covers 5 x 5 chunks of 64 m, so
the ring count needs deciding against the 24 m chunk this module uses.

### Textures

One 256 x 512 bark pair per species (eleven, since no two species share both a
style and a colour) and one 128 x 128 sheet per leaf kind (five). The cache is
per (style, colour) and per kind, so the eight prototypes of a stand draw one
bark sheet between them; the reference redrew a sheet per prototype. Verified:
building eight more meadow prototypes added no sheets.

### Build time

Not measured as a wall clock number, and it should be before this streams:
growing one prototype walks up to 1,400 axes and allocates a few hundred
thousand floats. Eight of them at chunk load time will be a visible hitch.
Build a type's stand once, off the streaming path, and keep it.

`placeTrees` is measured: 0.014 ms per 64 m chunk over 200 chunks.

## 5. What is unverified

- **Everything about how it looks.** There is no browser in this lane. The
  geometry is measured, the numbers are the reference's, and the shape claims
  in the test are geometric (willow's lowest foliage sits at -0.07 of its
  height against oak's +0.17; every palm frond is above 0.35 of the trunk;
  sakura's crown is 10.5 m across on a 6.6 m tree). Whether a willow reads as a
  willow on screen is not something a triangle count can tell you.
- **The GLSL.** The gust and swing expressions in `windHook` are a literal
  transcription of `gust()` and `swing()` in JS, and the test proves the JS
  side is bounded and that the strings land in the shader with the uniforms
  shared. Nothing has compiled them. The first browser run should check the
  console for a shader error before judging the sway.
- **Spruce's lowest whorl droops below the origin**, to -2.5 m at the needle
  tips on a seed 1 spruce. That is the reference's own behaviour: `gravity` is
  multiplied by 1.6 on a conical habit and the lowest whorl starts one segment
  up from a trunk that itself starts at `-0.4 * scale`. Planted at ground level
  the bottom skirt buries. Leave it (it reads as undergrowth, and on a slope it
  is invisible) or lift the record by `-minY * 0.5`. Flagging it rather than
  silently changing a reference number.
- **The four new species' parameters are mine.** They are written in the
  reference's language and produce trees inside their declared height ranges
  with sane triangle counts, but no one has looked at them.
