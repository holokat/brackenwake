## 1. Wiring Fable has to do

Nothing in section 1 is optional. **Until the first two land, none of this file
is in the bundle at all**: `vite build` is clean because nothing imports
`app/systems/story.js`.

### 1.1 `src/game/app/systems/index.js`: register the system

```js
import { story } from './story.js';
```

`FRAME_ORDER` and `SYSTEMS`, with `story` after `dragon` and before `ui`:

```js
export const FRAME_ORDER = ['world', 'player', 'emotes', 'combat', 'abilities', 'inventory', 'world_life', 'events', 'dragon', 'story', 'ui', 'context_menu', 'dev', 'input'];

export const SYSTEMS = [world, player, emotes, combat, abilities, inventory, world_life, events, dragon, story, ui, context_menu, dev, input];

```

Its `deps` are `['world', 'player', 'combat', 'world_life', 'events', 'dragon', 'ui']`
and are declared in the system itself.

**Why there.** It reads three things another system settled this frame: the
townsfolk it puts names on are restreamed in `world_life.update`, the Tithe
Wagon's position is `events.update`'s, and the dragon's own frame has already
run, so `dragon.grant` grows the animal and `ui.late` draws the Bond arc and the
thirteenth cell in the same frame the gift lands. It must also come **before
`input`**, because it takes the click on the six named bodies `input.route` has
never heard of, and a person in front of a house takes the click.

### 1.2 `src/game/state.js`: two keys on the character

In `blankCharacter()`, beside `opened`:

```js
    story: null,          // the first hour: which beats have been said (S2)
    waystones: null,      // the stones touched, and when each last carried you (S2)
```

In `hydrate()`, beside the `opened` line:

```js
  // the first hour (S2): a beat fires once per character, ever, so the list has
  // to survive a reload or Old Wynn tells you about the Standing Hedge again
  // every time the game is opened
  if (raw.story && typeof raw.story === 'object' && !Array.isArray(raw.story)) doc.story = { ...raw.story };
  // and the stones this character has put a hand on, with the day clock stamp
  // of the last time each one carried them (S2). story_runtime.js and
  // waystones.js both read their own record defensively, so a half written one
  // is read down to what is really in it rather than thrown away.
  if (raw.waystones && typeof raw.waystones === 'object' && !Array.isArray(raw.waystones)) doc.waystones = { ...raw.waystones };
```

Without these, both records still live on the character in memory, so every rule
holds inside a session and only the reload loses them. The save writes the whole
document, so both are already WRITTEN to localStorage today; it is `hydrate` that
drops them on the way back in. The system calls `state.touch('story')` on the
save tick, which `notify` already accepts.

### 1.3 `src/world/megalith_models.js`: the Standing Hedge's nine stones are waystones

**This one is load bearing.** The first hour tells the player to go and put a
hand on one of the nine, and today a ray onto one of them comes back as an
ordinary site hit. The seven town stones already carry `userData.waystone`
because `town_models.js` tags them after its merge; the nine do not.

Measured: after `mergeByMaterial`, the Standing Hedge's body is exactly **two**
meshes, one of `M.stonePale` with **108 triangles** (nine boxes) and one of
`M.stone` with 972 (the caps and the eighty boundary stones). The nine tall
stones are the only thing in that body built out of `M.stonePale`, so the pale
mesh IS the nine. In `buildMegalith`, after the `merged.traverse` that writes
`userData.site`:

```js
  // S2: the Standing Hedge's nine tall stones are the only thing in that body
  // built out of M.stonePale, so after the merge the pale mesh IS the nine, and
  // a ray onto one of them has to come back as a waystone. See S2.md.
  if (site.sub === 'waystones') merged.traverse((o) => { if (o.isMesh && o.material === M.stonePale) o.userData.waystone = true; });
```

`world_runtime.pick` already carries the flag out (T1.md, wiring 1), so this one
line is the whole of it. Verified in node that `o.material === M.stonePale` still
holds after the merge.

## 2. What was built, and the decisions inside it

### 2.1 The cast, and the role that was not added

Ten people. Three of them keep a building Hearthhome already has and are given
their names where they stand: **Nan Ockley** takes the Innkeeper's door at the
Bracken Arms, **Cobb Ashby** the forge, **Alys Fenn** the healer's. Six have no
building and get a body of S2's own: **Bram Haywood**, **Old Wynn Ashby** and
**Pip** on the green, **Ivy Weir** at the Mill Run, **Captain Serle Vane** at his
camp where the Kingsroad comes in, and **the Miller's Son** in Highwayman's
Hollow. The tenth, **the Skeleton Sexton**, has no body of S2's at all: he is the
monster runtime's to raise, and he speaks once, when the bell is rung.

**The contract asked for roles to be added to `src/mmo/npcs.js` and none were.**
Adding one breaks two things in files S2 does not own, and both break at load
rather than in a test:

- `npcs_runtime.auditNpcSpots()` runs at import and throws for any id in `NPCS`
  with no entry in its `ROLE_TINT`, so a new role would stop the game booting;
- `src/mmo/npcs.test.mjs` line 56 reads `NPC_LIST.length === 15`.

And a third thing that is not a crash and is worse: a role with
`appearsIn: ['town']` joins the pool `npcsFor` draws from, so a Farmer would
appear in the square of the Canopy Court and Cinderport as readily as in
Hearthhome. So the six carry `STORY_ROLES` in `story.js`, which are the same
shape a role in `npcs.js` is and are read by the same `createTalkEngine` and
`tabsFor`. If they are ever wanted in the table it is three lines rather than
one: the role, a tunic colour in `npcs_runtime.ROLE_TINT`, a `needs` gate nobody
supplies so no town rolls one, and the count in `npcs.test.mjs`.

A named person changes exactly two things in the Talk panel: the name at the top
and the lines on the Talk tab. Every other tab is still the role's, so Cobb Ashby
keeps the Blacksmith's shelf, prices and repair. Measured: his shelf is the same
25 rows, and a longsword bought off him goes through the same `buy`.

A person whose role trades in nothing opens on Talk alone, and `auditStory`
demands that such a person say why in `talkOnly`, in words: Old Wynn "has nothing
to sell and nothing to drill. What she has is the word Dragonsworn, and where the
Eyrie is."

### 2.2 The first hour

Seven beats. Each has a trigger the code reads off one plain object, the VIEW,
built by `story_runtime.viewNow()` off the running world and off nothing else.

| beat | trigger | who speaks | what it changes |
|---|---|---|---|
| `arrival` | inside Hearthhome, 110 m | Old Wynn | the compass turns to the Standing Hedge |
| `firststone` | one waystone owned | Old Wynn | nothing; it says what the network is |
| `tithewagon` | the Tithe Wagon within 140 m | Bram | nothing; Vane's name and what the tithe is |
| `firstwolf` | a wolf killed with the day factor under 0.4 | Bram | nothing; the Hangar's wolves, and Old Grist |
| `cellarsmouth` | within 45 m of the Old Cellars | Pip | nothing; Oram went down with the shell |
| `oram` | `oramBlackhand` killed | Pip | `dragon.grant('greenwold')`, the first Wyrmsoul |
| `chapelbell` | the bell rung | the Sexton | nothing; see 1.7 |

**The realm is checked twice**, once before the loop reads any beat and once
inside every trigger. One gate is a gate; two are a rule.

**Wyrmsoul is handed over through the API that already exists.** `dragon.js`
exports `grant(giftId)` on the entity, it is the call D2's dungeons were built to
make, and it says its own line ("takes back the base from the Greenwold") and
grows the animal on the spot. S2 adds the sentence that says what the player can
now do, because the existing line does not: "Wyrmsoul is yours. Fill the Bond and
the last cell of the bar lights, and for six seconds the world moves at a fifth
of your speed while you do not." No hook was needed.

**Effects say what did NOT happen.** A character who has set their own map
waypoint keeps it, and is told: "Your compass is already set on a mark of your
own, so the ring is not marked over it. The Standing Hedge is out there whether
or not the needle says so." A dragon that already holds the gift is told so. A
game with no dragon at all still fires the beat and says the shell passed between
you and nobody.

### 2.3 The waystones

The sheet's sentence, clause by clause, each a gate with words:

> Touch a stone with the dragon awake and it is yours; from then on any waystone
> carries you to any other you own, once a day per stone. The Legion has tried
> for a century and been refused.

Sixteen stones, none of them placed by this file. Seven are read off
`town_layout.layoutTown(site, 0).waystone`, which is the same plan `town_models`
builds the stone from and the same seed `npcs_runtime` reads. Nine are the
Standing Hedge's, rebuilt on the same two numbers `megalith_models.waystones`
uses: a radius of 805 m and nine. **`HEDGE_R` is a copy** and the test says so:
`zones.BODY_R.waystones` is 811, which that file sets as `R + 6`, and
`waystones.test.mjs` asserts `HEDGE_R + 6 === BODY_R.waystones`, so widening the
ring without telling this file is a failing test rather than stones drifting
apart in silence.

**Which of the nine is which.** The sheet says they are "each twinned with a
stone in another realm", so each carries a realm: the nine realms are sorted by
their bearing from the middle of the ring and laid onto the nine in that order,
at the rotation that puts every realm nearest its own side. Worked out at load
from `realms.js` alone, so moving a realm moves its stone. Measured: a bijection,
worst mismatch **59 degrees**. Two of the nine are twinned with realms that have
no stone raised yet (the Boneyard and the Sunken Kingdom have no precinct town),
and the picker says so rather than showing a name with nothing behind it.

**A day is the day clock's day**, `DAY_CYCLE_MS`, 25 real minutes. The stone you
LEAVE is spent; the one you arrive at is not. A clock that has gone backwards, a
save from another session, clears rather than freezing a stone for ever.

The picker is a window of its own rather than a tab of Talk, because a stone is
not a person and the Talk panel's whole shape is a role's shelf. It is registered
by the system rather than by `ui.js`: `windows.register` is the whole of what it
takes, and `ui` is built first and cannot hold a wire to a panel that does not
exist yet.

### 2.4 The click, and where a body comes from

`npcs_runtime` streams and clicks its own people and knows nothing about S2's, so
the six named bodies are raised by `story_runtime`: `player.buildCharacter`,
tinted per story role, a plate on a layer of its own, the same turn toward you and
the same 4 m reach, and the click routed through the system's `click` phase.

It refuses the click in exactly the cases the router would want it to: a held
spell is choosing a victim, a window is open, the bench is on, the player is
dying. When no named body is under the ray it asks `runtime.pick` and, if the hit
carries `waystone`, puts your hand on the stone. One gesture, two answers: a
stone you do not hold becomes yours, and a stone you already hold opens the
picker with itself as the door you are leaving by.

## 4. What is NOT verified

- **Nothing has been seen in a browser.** Every measurement above is node. What
  a named person's body looks like standing on the green, whether the plates
  collide with the townsfolk's, whether the picker's window reads well, and
  whether a hand on a stone at the Standing Hedge feels like anything are all
  unverified.
- **None of it is in the bundle** until section 1.1 lands. `vite build` is clean
  because nothing imports the system. The three runtimes are proved against the
  real tables in node; the frame that reaches them is not.
- **The click has not been driven through the real router.** The system's `click`
  phase is written and its ordering argued; no ray has been cast at a real body
  in a real scene, and the interaction between it and `input.route` has not been
  run.
- **The teleport has not been taken.** `travel` is measured through a recorded
  teleport function, so the arithmetic and the cooldown are proved and the five
  things a warp is (out of a dungeon, the feet, the camera, the document, the
  rescan) are copied from `win_dev.warp` and have not been run.
- **`character.story` and `character.waystones` do not survive a reload** until
  section 1.2 lands. Both are written and read on the character either way, so
  once-ever holds inside a session and only across one is missing.
- **The nine stones cannot be touched** until section 1.3 lands. The seven town
  stones can.
- **The chapel bell cannot be rung** by anything at all. See 1.7.
- **Old Grist is not in the game.** The row, the habitat line and the
  documentation line are written here and measured on a copy; none of them is in
  `src/mmo/monsters.js`, which S2 does not own.
- **The wagon beat has not met a real wagon.** It reads `events.active()` and is
  driven with a real-shaped record; E2's own wagon has not been walked up to.
