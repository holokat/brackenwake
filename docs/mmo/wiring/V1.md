# V1: the sky and the water

Two files, one shader. `src/game/sky.js` paints the dome and `src/world/water.js`
paints the sea, and both reflect the same `skyCol` because water.js concatenates
sky.js's GLSL string rather than keeping a copy of it.

| file | what it is | tests |
| --- | --- | --- |
| `src/game/sky.js` | the analytic dome, the day palette, the sun arc | `sky.test.mjs`, 55 checks |
| `src/world/water.js` | the ocean sheet, the Gerstner waves, the refraction pass | `water.test.mjs`, 79 checks |

Nothing outside those four files was touched. `scene.js`, `chunks.js`,
`world_runtime.js` and `main.js` all need edits, and every one of them is listed
below.

---

## 1. The create calls

Both are built once, at boot, after `createScene` and after the world runtime
(the water reads `field.seaLevel`).

```js
import { createSky, skyColours } from './sky.js';
import { createWater } from '../world/water.js';

const sky = createSky(sc);                                  // adds a group named 'sky'
const water = createWater(sc, runtime.field, { sky });      // adds a group named 'water'
```

Passing `{ sky }` is what makes them one sky and not two: the water then shares
the sky's uniform block, and `sky.update` is the only writer of the sun
direction, the palette and `uTime`. `water.writesSky` reports `false` in that
case. Built without a sky (`createWater(sc, field)`), the water owns its own
block and reads the `sunDir` and `colours` arguments to `update` instead; both
paths are tested.

`createSky(sc)` uses `sc.scene` only. `createWater(sc, field, opts)` uses
`sc.scene` and reads `field.seaLevel` (`-0.8`). Neither touches the renderer at
construction time, which is why both build in node and why the tests are real.

Options worth knowing: `createSky(sc, { radius, cloud, cycleS, maxElevation,
noonAzimuth })`, `createWater(sc, field, { sky, quality, seaLevel, far,
manageShadows })`.

## 2. The frame

In `main.js`, replacing the last three lines of `frame()`:

```js
sc.follow(centre);
sc.setDay(day);                                             // unchanged
sky.update(day, sc.camera.position, dt, now);               // camera, not player
water.update(dt, sc.camera.position, sky.sunDir, sky.colours, now / 1000);
water.beforeRender(sc.renderer, sc.scene, sc.camera);       // the refraction pass
sc.render();
```

The order is load bearing:

- **`sky.update` before `water.update`.** The water reads the sky's uniforms
  through the shared block; the sky is what fills them.
- **the camera position, not the player's.** The dome and the sheet both centre
  on the eye. `sc.follow` centres the old sky on the player, which is fine for a
  dome of radius 1500 and wrong for a water sheet whose innermost triangles are
  1.5 m across.
- **`nowMs` on `sky.update`.** Without it the sky recovers the phase by
  inverting `dayFactorAt` where the curve is moving and integrating `dt` across
  the flat noon and midnight. That works (measured: no drift over a simulated
  day at 0.5 s steps) but it depends on frames not being dropped. With `now` it
  is exact by construction.
- **`beforeRender` immediately before `sc.render`.** It renders the scene once
  more, with the water hidden, into a half resolution target that carries a
  depth texture. Anything that moves the camera or the world after it and before
  `sc.render` will show as a smear in the refraction.

`beforeRender` returns `true` if it did a pass and `false` if it skipped, which
it does on `low` quality and whenever the water group is invisible.

### The shadow map

Two renders of one scene is two shadow map builds. `beforeRender` builds the map
during its own pass and then sets `renderer.shadowMap.autoUpdate = false` so the
main pass reuses it: the water casts no shadow, so both passes want the same map
anyway. It hands `autoUpdate` back the moment it skips a pass, so shadows do not
freeze underground or on `low`. Pass `{ manageShadows: false }` to opt out.

## 3. What has to change in the files I do not own

### `src/game/scene.js`

1. **Switch off the old sky.** `skyDomes`, `sunBall`, `sunGlow` and `moon` sit at
   radius 1495 to 1500 and would paint straight over the new dome, which is
   drawn first with `depthTest: false`. Remove them, or set `.visible = false`
   on all four. `scene.background` can stay: the dome covers it.
2. **Drive the lights off the palette.** In `setDay`:

```js
import { skyColours } from './sky.js';
// ...
const p = skyColours(d);
sun.color.setRGB(p.sun.r, p.sun.g, p.sun.b, THREE.SRGBColorSpace);
hemi.color.setRGB(p.zenith.r, p.zenith.g, p.zenith.b, THREE.SRGBColorSpace);
if (!fogPinned) scene.fog.color.setRGB(p.fog.r, p.fog.g, p.fog.b, THREE.SRGBColorSpace);
```

   `skyColours` is pure and takes only the day factor, so `setDay` keeps its
   signature and stays testable. The `SRGBColorSpace` argument matters: the
   components it returns are authored sRGB and the renderer works in linear.
3. **Point the sun where the sun is.** `follow(pos)` currently pins the light at
   a fixed `(+90, +120, +50)` offset, so shadows never move all day. Replace with:

```js
sun.position.copy(pos).addScaledVector(sky.shadowDir, 220);
sun.target.position.copy(pos);
sun.target.updateMatrixWorld();
```

   `sky.shadowDir` is `sky.lightDir` (the sun by day, the moon by night) with its
   elevation floored at `SHADOW_MIN_Y = 0.25`, about 14 degrees, and renormalised.
   A directional light lying flat on the horizon throws shadows far longer than
   the 55 m shadow box in `scene.js`, and they clip. The floor is measured: over
   a full day the lowest `shadowDir.y` is exactly 0.250.
4. Keep `WORLD_FOG` and the fog distances as they are. World runtime already
   sets near 90, far 536, and the water reads those off `scene.fog` every frame
   so sea and land vanish on the same line.

### `src/world/chunks.js` (V3 owns it)

**Rivers: does chunks.js draw river water today?** No. There is no river
specific water anywhere. What it does is give every chunk that has any vertex
below `SEA_LEVEL + 0.2` a flat `PlaneGeometry(64, 64)` quad at
`WATER_Y = SEA_LEVEL - 0.06` with a translucent `MeshStandardMaterial`. That one
quad is the sea, the lakes and the rivers all at once.

**It has to go.** The new sheet covers the same ground at the same height and the
two will z-fight. Delete the `hasWater` branch in `build()`, the `waterMat`, and
the `water` field of a chunk record (and the disposal of it). `hasWater` itself
can stay; nothing else reads it.

**Rivers, if anyone ever draws ribbons.** `water.riverMaterial(flow, over)`
returns the same shader on the plane vertex path with the waves down to a
ripple (`uWaveH` 0.05, `uSteep` 0.15, `uWaveScale` 0.25) and the detail noise
dragged along `flow` (`{ x, z }`, world units per second). It shares every
uniform slot with the ocean except the ones it overrides, so the one refraction
pass feeds it too. Use it on a ribbon mesh in the `water.group`.

Nothing needs it today, and this is the reason:

> Measured over an 8 km square at 17 m steps: 438 river core samples
> (`river > 0.95` on land), **0 of them above sea level**, deepest -1.80 m.
> `field.js` carves every river core to exactly `bed = -1.8` while `SEA_LEVEL`
> is `-0.8`, so the single sheet floods every river to a metre deep. One
> transect measured a flooded channel 44 m wide.

### `src/game/world_runtime.js` (Fable owns it)

`SKY_AND_LIGHTS` hides the overworld by **name** when you go underground. The
sky group is named `'sky'` on purpose so it is already covered. **Add `'water'`
to that set** or the ocean hangs in the dungeon:

```js
const SKY_AND_LIGHTS = new Set(['sky', 'water', 'sun-light', 'hemi-light', 'ambient-light', 'fill-light']);
```

Two scene children named `'sky'` is fine: `overworldNodes()` collects into a
`Set` by name and both get hidden. If the old domes are deleted rather than
hidden there is only one.

### Underwater

`water.underwater` is true when the camera is below the surface, waves counted
(`water.surfaceAt(x, z)` is sea level plus the Gerstner height). The water
shader already darkens and murks itself; the terrain does not. When it flips,
pin the fog:

```js
if (water.underwater !== wasUnder) {
  wasUnder = water.underwater;
  if (wasUnder) sc.setFog(0.5, 45, 0x0b3550);   // uDeep
  else sc.setFog(90, 536);                       // hands the colour back to setDay
}
```

`sc.setFog` with a colour pins, without one unpins, which is exactly the
behaviour the dungeon descent already relies on.

## 4. Fog

| where | near | far | colour |
| --- | --- | --- | --- |
| open world | 90 | 536 | `skyColours(day).fog`, set in `setDay` |
| underwater | 0.5 | 45 | `0x0b3550` (the water's `uDeep`), pinned |
| dungeon | unchanged | unchanged | unchanged |

The water reads `scene.fog.near`, `scene.fog.far` and `scene.fog.color` off the
scene every `update`, so there is nothing to keep in step by hand.

## 5. Uniforms for the settings window

Both objects expose `uniforms` directly, and everything below is safe to change
at any time from a slider. Nothing here needs a rebuild.

**Sky** (`sky.uniforms`, plus the methods):

| control | call | range |
| --- | --- | --- |
| cloud cover | `sky.setCloud(v)` | 0 clear to 1 solid, default 0.45 |
| time of day | `sky.setPhase(p)` | 0 midnight, 0.5 noon (the dev bench time slider) |
| glare | `uGlare.value` | 0.45 to 1.13 across the day, driven |
| stars, moon | `uStars`, `uMoonUp` | driven by the day, 0 to 1 |

**Water** (`water.uniforms`, plus the methods):

| control | uniform | default | what it does |
| --- | --- | --- | --- |
| quality | `water.setQuality('high'\|'medium'\|'low')` | high | grid and refraction |
| wave height | `uWaveH` / `setWaves({height})` | 0.30 | crest is 2.41x this |
| choppiness | `uSteep` | 0.45 | how far a crest leans, and the crest foam threshold |
| wave scale | `uWaveScale` | 0.85 | multiplies every wavelength |
| wind direction | `uWindDir` | 0.61 rad | added to every wave angle |
| wave speed | `uSpeed` | 0.9 | |
| detail | `uDetail` | by quality | the fragment ripple normal |
| reflectivity | `uReflect` | 1.0 | scales the fresnel |
| refraction | `uRefract` | 0.055 | how far the normal bends the scene sample |
| foam | `uFoam` | 0.85 | |
| subsurface | `uSSS` | 0.8 | light through the back of a crest |
| clarity | `uMurk` | 0.9 | higher is murkier |
| shore depth | `uShoreDepth` | 1.6 m | how deep the foam band reaches |
| deep, shallow | `uDeep`, `uShallow` | `0x0b3550`, `0x2f9c98` | |
| sea level | `water.setSeaLevel(y)` | field's `-0.8` | |

Read only, useful on a debug panel: `water.stats` (`passes`, `skipped`,
`rtPixels`, `mainPixels`, `verts`), `water.quality`, `water.underwater`,
`water.shadowsHeld`, `sky.phase`, `sky.palette`.

## 6. What was measured

Everything in this section is a number the tests print, not an estimate.

**The sheet, and what the refraction pass costs.**

| quality | grid | vertices | triangles | target at 1600x900 | at 3840x2160 |
| --- | --- | --- | --- | --- | --- |
| high | 192 | 36 864 | 72 962 | 800x450, 25% of a full extra pass | 1920x1080, 25% |
| medium | 128 | 16 384 | 32 258 | 560x315, 12% | 1344x756, 12% |
| low | 96 | 9 216 | 18 050 | no pass at all | no pass |

Vertex spacing on the warped grid, metres, measured with `spacingAt`:

| distance | 5 m | 10 m | 25 m | 50 m | 100 m | 250 m | 500 m |
| --- | --- | --- | --- | --- | --- | --- | --- |
| high | 1.50 | 2.14 | 3.47 | 5.01 | 7.27 | 11.90 | 17.31 |
| medium | 2.33 | 3.31 | 5.31 | 7.64 | 11.03 | 18.01 | 26.15 |
| low | 3.23 | 4.54 | 7.23 | 10.35 | 14.89 | 24.23 | 35.13 |

The longest wave is 42 m and the shortest 3.2 m. Only the long waves are carried
by the vertices; the short ones live in the fragment normal, which is how the
reference did it too.

**The frame cost of the pass, as far as it can be counted without a GPU.** One
extra `renderer.render` of the whole scene into a target with 25% of the screen's
pixels, one shadow map build shared between the two passes rather than one each,
and one extra program variant per material because three compiles tone mapping
out when it renders into a target. The GPU cost of that pass is **not measured**;
see section 7.

**The waves.** Over 4000 points at one instant: crest range -0.692 to +0.681 m
against a cap of 0.723 m (`AMPLITUDE_SUM * height`), peak to trough 1.374 m.
0.4 s later 3997 of 4000 points had moved by more than 0.1 mm. `gerstnerAt` runs
at 2.21 million calls a second, so floating a boat on it is affordable.

**The wave table is one table.** The test parses the six `waveParam` lines out of
the GLSL source and compares them to the exported `WAVES` array. With the
steepness at zero the height reduces to a plain sum of sines, and the test
recomputes that sum from the shader's own numbers with its own arithmetic: worst
disagreement 0.0e+0 over 200 samples.

**The sky palette.** Noon zenith luminance 0.439 against midnight 0.028, 15.8x.
Dusk sun warmth (red over blue) 0.765 against noon 0.161; dusk horizon 0.631
against noon -0.125. By day the horizon reads 0.928 against a zenith of 0.439.
Across 101 samples of the day every component stays inside 0 to 1 and the zenith
never darkens as the day comes up.

**The sun agrees with the clock.** Over three simulated days at 0.5 s steps,
2160 samples, the sun is above the horizon on exactly the samples where
`scene.js`'s `dayFactorAt` reads above 0.5: 0 disagreements. One sunrise and one
sunset a day, noon reaching 1.050 rad and midnight -1.050. Sunrise and sunset
azimuths are 3.142 rad apart, so the sun does not rise where it set. The
clockless fallback tracked the clock to 0.0 s over a full day of 0.5 s frames.

**The refraction pass does what it says.** Driven by a recording renderer:
exactly one extra `render`, the water group invisible during it, visible again
after, the previous render target restored, the target sized to half the drawing
buffer, and `uResolution` set to the **main** buffer size and not the target's
(`gl_FragCoord` is in main pass pixels). Hidden water does no pass at all and
clears `uHasDepth`. `low` does no pass and drops the target.

**Where the water goes.** 438 river core samples across 8 km, none above sea
level, deepest -1.80 m. A beach transect at (0, 232) has a 4.5 m wide band
shallower than the 1.6 m foam depth, so shore foam has somewhere to sit.

**The shaders parse.** All five assembled sources (sky vertex and fragment, ocean
vertex, pool vertex, water fragment), wrapped in a reconstruction of three's
`ShaderMaterial` prefix with the `#include` chunks resolved from three's own
`ShaderChunk`, parse as GLSL ES 1.00 with no undeclared name. The check was
driven the other way too: it fails on a missing semicolon, on `toCamm` for
`toCam`, and on `skyColour()` for `skyCol()`.

**`npm test`.** `sky.test.mjs` 55 passed, `water.test.mjs` 79 passed. Four other
suites were red while this was written (`flora`, `tree_gen`, `terrain_material`,
`world_runtime`), all from V2's and V3's in-flight edits to files I did not
touch; `world_runtime` fails with `TypeError: Assignment to constant variable`
out of the modified `flora.js`.

## 7. What is not verified

- **Nothing has been on a GPU.** No browser was available. The shaders parse and
  their uniforms are all provided, but GLSL type checking, linking, and every
  question of how it actually looks are open. A `glslangValidator` binary was
  installed and turned out to be x86 only on this arm64 machine with no Rosetta,
  so semantic compilation did not happen either.
- **The cost of the refraction pass in milliseconds.** Counted in pixels and
  draw calls, never timed.
- **The depth reconstruction.** `sceneEyeDepth` inverts a perspective depth
  buffer with the standard formula and the shore foam depends on it being right.
  Untested without a GPU. If shore foam appears everywhere or nowhere, that
  function is the first place to look.
- **Colour space.** The reasoning is that a `ShaderMaterial` rendered into a
  render target gets no tone mapping (three sets `toneMapping = NoToneMapping`
  whenever `_currentRenderTarget !== null`, verified by reading
  `WebGLRenderer.js`), so the refraction target holds linear colour, which is
  mixed in linear and tone mapped once at the end. That is read off the source,
  not observed.
- **The look.** Every constant in the palette and every wave amplitude is a
  judgement, not a measurement. They are all uniforms; turn them.

## 8. What was invented, and why

- **The day palette.** The reference ships five discrete sky presets. This is
  five keyframes on the day factor instead, because `scene.js` hands over one
  number and the palette has to be continuous. The gold sits at day factor 0.5
  because that is arithmetically the moment the sun crosses the horizon:
  `scene.js`'s curve is a clamped cosine, so `elevation = MAX_ELEVATION *
  ((d + 0.2) / 0.7 - 1)`, which is zero at 0.5.
- **The phase.** The day factor cannot tell morning from evening (it is
  symmetric) and stops moving for a quarter of the cycle at each end. The sun
  needs a real clock position, so `phaseFromClock(nowMs)` inverts the same 0.12
  offset `dayFactorAt` uses.
- **Stars and the moon are in the shader**, not sprites: a procedural star field
  on a cube grid so it is fixed to the sky, and a moon disc opposite the sun.
- **The sea is a coast, not an ocean.** Wave height 0.30 against the studio's
  0.75, scale 0.85. 1.37 m peak to trough.
- **No ripple simulation.** The studio's 256x256 wave equation and its sixteen
  impulse sources were left out. Nothing in the game drops a stone in the water
  yet. If something does, that is where it goes.
- **The shadow map sharing and `shadowDir`.** Neither was asked for. Both exist
  because a second full scene render and a sun that swings all the way to the
  horizon each break something that was working.
