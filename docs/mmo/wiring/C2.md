# C2 wiring: the con colours

Files owned and changed: `src/game/con.js` (new), `src/game/con.test.mjs`
(new), `src/game/targeting.js`, `src/game/targeting.test.mjs`,
`src/game/target_ring.js`, `src/game/target_ring.test.mjs`, `src/game/hud.js`,
`src/game/hud.test.mjs`, `src/game/floaters.js` (colours only),
`src/game/floaters.test.mjs`, `src/game/app/systems/ui.js` (the hover text
lines only), and this note.

Nothing in `src/mmo/` was touched. `monsters.js`, `combat.js`, `abilities*.js`,
`dragon*.js`, `wyrmsoul*.js` and `creation.js` were read and not edited.
`win_dev.js` is untouched, and `con.test.mjs` has a check that keeps it that
way: the dev bench readout prints tiers and numbers, and colouring it would
turn a diagnostic into a decoration.

## The rule

`15-PROGRAMME.md`, "Difficulty and colour". `con.js` is the whole of it and is
pure: no THREE, no DOM, no state.

```js
playerTier(character)   // the tier band their best attack skill falls in
conOf(monster, character)
// -> { tier, mine, delta, level, colour, word, skull }
```

| the monster, against you | level | colour | the words | skull |
| --- | --- | --- | --- | --- |
| two tiers or more below | `trivial` | `#9aa0a6` grey | no threat | |
| one below | `easy` | `#7ee07a` green | easy | |
| the same | `even` | `#ffd23f` yellow | a fair fight | |
| one above | `hard` | `#ff9a3c` orange | dangerous | |
| two or more above | `deadly` | `#ff5a4d` red | it will kill you | yes |
| a boss, whoever is looking | `boss` | `#c07bf0` purple | a boss | yes |

The five below the boss are floaters.js's own palette, unchanged, so a grey
"dodge" and a grey name are the same grey. `ui_theme.js` has no con palette of
its own (stone, parchment, gold, three pools, six item rarities) so these are
fixed hexes and `con.js` is where they live. The purple is deliberately **not**
items.js's epic purple `#a335ee`: that hex already means "an epic item" in the
bag and on every loot label, and a boss's name is not an item.

The bands are `mmo/monsters.js` TIERS read at import, never a second copy:
`PLAYER_TIER_FLOORS` comes out `[0, 10, 30, 50, 70, 90]`. The skills are
`items.js` COMBAT_SKILLS (eleven: the melee and ranged groups) plus the four
schools that attack, magery, necromancy, mysticism and chivalry: fifteen in
all, every one proved to be a real skill id by `auditCon()`, which runs at
import and throws.

Two decisions worth writing down:

- **A player is never tier 6.** Tier 6 is the boss band and carries tier 5's
  numbers, so a grandmaster allowed to stand there would read every champion as
  his own colour and the purple would say nothing. `MAX_PLAYER_TIER` is 5.
- **A boss is purple however you got there.** `boss === true` or `tier >= 6`,
  and the delta is not consulted. A champion is not "one above" anybody.

## Every surface that names a monster

| surface | file | what it reads |
| --- | --- | --- |
| the target frame's name and the word beside the health | `hud.js` `drawTarget` | `targetFrame(target, character).colour` / `.word` |
| the nameplate over the current target | `hud.js` `setNameplate`, projected by `targeting.js` | the whole `conOf` |
| the skull before a red or purple name | `hud.js` `SKULL_MARK` | `.skull` |
| the hover hint under the cursor | `app/systems/ui.js` `updateCursor` | `conLabel` and `conOf(...).colour` |
| the target ring | `target_ring.js` `tintFor` | the level |
| the number you take from a red or purple monster | `floaters.js` `colourFor` | the level |
| the dev bench readout | `win_dev.js` | **nothing, on purpose** |

### The one call that drives four of them

`targeting.frame(character)` is called once a frame by `app/systems/ui.js` in
`draw`, which is where the character is known. It already built the target
frame; it now also

```js
hud.setNameplate(plate);          // projected through sc.camera this frame
setAnger(f ? f.level : null);     // floaters.js
setRingCon(f ? f.level : null);   // target_ring.js
```

and clears all three when there is no target and on `dispose`. **No call site
outside these files changed.** `app/systems/combat.js` still calls
`targetRing.update(dt, target, attacking, groundY)` with the same four
arguments and `context.js` still builds the floaters the same way.

That last point is why the anger and the tint are pushed rather than passed:
`combat.js` hands a floater the **defender** and never the attacker, and the
ring is updated from a system this agent does not own. The player's current
target is the honest available stand-in for "what is hitting me", and it is
written down in `floaters.js` rather than implied: a third party hitting you
while you look at something harmless paints the ordinary red.

### The nameplate

`targeting.js` projects, `hud.js` paints. `nameplateOf` returns
`{ name, colour, word, level, skull, x, y }` in pixels from the top left of the
HUD, or null (no target, a corpse, or behind the camera). The viewport is the
renderer's canvas, `opts.viewport()` in a test.

It hangs `PLATE_LIFT` 0.55 m over the top of the body, and the body's height is
W2's own `monsters.forActor(actor).model.height` when W2 is there to ask, 2 m
when it is not. A **boss** takes `BOSS_PLATE_LIFT` 1.9 m instead, because
`monsters.js` already hangs a canvas sprite at `model.height + PLATE_LIFT`
(1.1 m) that is 0.7 m tall, so the top of that sprite is `model.height + 1.45`
and 1.9 clears it. Two labels stacked would be worse than one.

The plate is `pointer-events: none` and moved with one `transform`, and its
words are re-strung only when they change, so a plate that is only following
costs one style write a frame.

### The ring

Gold stays gold for a fair fight, exactly, and red-and-breathing while you are
attacking, exactly: those two already mean something a player has learnt. Every
other level pulls the gold `RING_TINT` 0.55 of the way toward the con colour.
The boss is the exception at `BOSS_TINT` 0.8, because gold and purple mixed
evenly go pink (`#cb93a5`, a mauve nobody would call purple) long before they
go purple.

| level | ring |
| --- | --- |
| trivial | `#b6a77d` |
| easy | `#a7ca64` |
| even | `#d9b04a` (the gold, unchanged) |
| hard | `#eea442` |
| deadly | `#ee814c` |
| boss | `#c586cf` |
| attacking, any level | `#e0463a` breathing (unchanged) |

### The floaters

Only `taken`, the number over **your** head, changes: `#ff5a4d` becomes
`#ff2a17` when the target reads `deadly` or `boss`. The same hue, deeper, so it
reads as worse without becoming a colour the player has to learn. Damage you
deal, crits, heals, misses, gains and gold are untouched.

## What was measured

`node src/game/con.test.mjs` 78 passed, `targeting.test.mjs` 82,
`hud.test.mjs` 173, `target_ring.test.mjs` 27, `floaters.test.mjs` 29.

- **Every tier against every player tier.** The 7 x 6 table is printed by the
  suite, and the checks read the printed grid: the diagonal is `even` six times,
  one below is `easy` five times, one above is `hard` five times, every cell two
  or more below is `trivial`, every cell two or more above is `deadly`, and the
  whole boss row is `boss` including against a grandmaster. 42 cells, all six
  levels, no gaps.
- **Both directions of the gate.** Three tiers below is still grey, four above
  is still red, and the raw delta comes back unclamped (+5 and -5).
- **The rule moves as the player trains.** The same wolf (tier 2, from the real
  table) walked against skill 0, 10, 30, 50, 70, 90, 100 gives
  `deadly, hard, even, easy, trivial, trivial, trivial`, and never climbs back.
  A mage doing the same in magery gives `deadly, even, easy, trivial`. The wolf
  row is JSON-compared before and after to prove nothing wrote to it.
- **All 48 rows in monsters.js** read as a level for a fresh character and for a
  grandmaster: 7 even, 7 hard, 30 deadly and 4 boss to a fresh character.
- **The frame's rendered pixels, three cases.** The real `createHud` against
  hud.test's fake document, driven with the real `targetFrame` and one real
  wolf: a fresh character gets `#ff5a4d` "it will kill you" with the skull on,
  a middling one `#ffd23f` "a fair fight" with it off, a grandmaster `#9aa0a6`
  "no threat". Each case checks the frame name, the frame word, the plate, the
  plate's skull class and the hint, all in the same colour. The Ashen King is
  purple to the grandmaster.
- **The hover hint's text.** `conLabel({name:'Wolf', tier:2}, ...)` is
  `"Wolf, a fair fight"` at skill 30 and `"Wolf, it will kill you"` at 0, and
  the HUD writes it with `color: #ffd23f` and `#ff5a4d`.
- **The nameplate following a moving target for 60 frames.** A real
  `THREE.PerspectiveCamera` at (0, 6, 14) looking at (0, 1, 0) on a 1280 x 720
  viewport; a wolf walking x -6 to +6. A plate on all 60 frames, x climbing
  383 px to 897 px with no step backwards, y inside the viewport the whole way,
  and every plate higher on screen than the feet it belongs to. A boss plate
  sits at 264 px where an ordinary one sits at 322 px. Behind the camera, a
  corpse, and no camera at all each give no plate rather than a wrong one.
- **The ring**, per level, printed and checked: `even` is `TARGET_COLOUR`
  exactly, all six levels are six different numbers, deadly is redder and less
  blue than gold, trivial's red and green have come together, the boss's blue
  is above its green, and a target you are FIGHTING wears the attack red at
  every one of the six levels.
- **The floaters**, per level: `taken` is angry for `deadly` and `boss` only,
  and `damage`, `crit`, `gain`, `heal`, `miss` and `gold` are unmoved by any
  level.
- **The consumers exist.** `con.test.mjs` reads the source of `targeting.js`,
  `target_ring.js`, `hud.js`, `floaters.js` and `app/systems/ui.js` and fails
  if the import or the use goes missing, and fails if `win_dev.js` starts
  reading the rule. That guard is there because this repo has shipped a writer
  with no consumer before. The checks say "read from source" in their names;
  what the surfaces DO with the rule is measured for real above.

## What was NOT measured

- **No browser.** Nothing here was seen on a screen. The plate's CSS
  (`display: flex`, `pointer-events: none`, `z-index: 29`, the `translate(-50%,
  -100%)`) is written and its classes are measured, but whether a purple name
  reads against a bright sky at dusk is a thing only Fable's eye can settle.
- **`app/systems/ui.js` has no suite** and cannot get one cheaply: its `create`
  needs a document, a renderer and a WebGL context. Its hover branch is proved
  by source read plus the two halves it is built from (`conLabel`, and the
  HUD's coloured `setHint`), not by running `updateCursor`.
- **`npx vite build` fails on `main`** as this lands, and not because of this
  work: `src/game/combat.js` imports `KINDS` from `src/world/fauna.js`, which
  F1's in-flight fauna change no longer exports. The C2 module graph was built
  on its own instead (a temporary lib entry over `con.js`, `targeting.js`,
  `target_ring.js`, `floaters.js` and `hud.js`): 18 modules transformed, no
  missing export, 339.72 kB. The temporary entry was deleted.
- **`npm test` is not green on `main`** for the same reason: 17 suites were
  failing before this work started, 14 of them on `fauna.js` no longer
  exporting `KINDS` and the rest on `realms.js` and `world_runtime.js`, all of
  them other agents' in-flight Wave A files. Every suite this agent owns is
  green.

One test outside the con was un-staled on the way past: `hud.test.mjs` asserted
`/<svg/` for an item bar cell's art, and the starting gear paintings turned the
potion into an `<img>`. It now accepts either, and prints the art it found.
