## 2. The one impure line, and why

`rollUnique` writes to `character.uniques`. Every other function in `loot.js`
is pure and this one is not, deliberately: "once per character" is only true if
the taking and the remembering happen in the same breath. A version that
returned the sword and left the caller to write it down is a version that
eventually ships with the writing missing, and the player finds the same sword
twice. `rollKill` calls it, so the mutation is on the path every kill takes.

## 3. The two call sites Fable wires

### a. `src/game/monsters.js`, the kill

Line 731 today:

```js
    const drop = loot?.rollFor ? loot.rollFor(mon.row, { luck: num(killer?.bonuses?.luck), seed: hashKey(mon.key) }) : null;
```

becomes:

```js
    const drop = loot?.rollFor ? loot.rollFor(mon.row, { luck: num(killer?.bonuses?.luck), seed: hashKey(mon.key), character: killer?.kind === 'player' ? playerCharacter : null }) : null;
```

`createMonsters` has no character today; it is handed `opts.deadUntil`, which
is one array off the document. Add the document beside it, in the same shape
and the same place as `deadUntil`:

```js
  const playerCharacter = (opts.character && typeof opts.character === 'object') ? opts.character : null;
```

next to `const deadUntil = ...` at line 597, name it in the `@param opts` block
above `createMonsters`, and pass it in
`src/game/app/systems/combat.js` where `createMonsters` is called:

```js
      deadUntil: character.deadUntil,
      character,                            // L1: the class the drops steer toward
```

`character` is already destructured out of `ctx` at the top of that system, so
nothing else moves. Gating on `killer?.kind === 'player'` matters: a monster
killed by the dragon or by another monster is not a kill the player's class
should steer, and it is also the kill that must not spend the player's one
shot at a unique.

### c. `src/game/state.js`, so the record survives a reload

`hydrate` rebuilds the character field by field, so anything it does not name
is dropped on the next save. `character.uniques` is not named, which means the
signature record would be lost the moment the player reloads and the same
unique would drop again. Two lines:

In `blankCharacter()`, beside `zones: []`:

```js
    uniques: [],          // signature uniques already taken (L1)
```

In `hydrate`, beside the `zones` line:

```js
  if (Array.isArray(raw.uniques)) doc.uniques = raw.uniques.filter((d) => typeof d === 'string');
```

Until that lands, the bias works fully and the uniques drop, but they can drop
a second time after a reload. This is the only part of L1 that is not complete
in the files this agent owns, and it is called out rather than left quiet.

## 4. The nine bosses, and the two joins

`SIGNATURES` names nine realm bosses, taken word for word out of `realms.js`.
The M2 roster landed while this was being written and all nine now resolve to a
real monster row:

| hundred_faces | `keeperOfFaces` | Verdant Deep, the Deep of Faces |
| thalassas_tooth | `thalassa` | the Saltmarch, the Leviathan's Rest |
| furnace_heart | `brassHeart` | the Ember Wastes, the Brass Works |
| hasks_reckoning | `wardenHask` | the Stormpeaks, the Eyrie's Roost |
| gallows_whistle | `huntmasterGallow` | the Boneyard, the Trophy Throat |
| cold_crown | `legateOssory` | Frostreach, the Vault Below |
| caradocs_ring | `kingCaradoc` | the Sunken Kingdom, the Drowned Palace |
| wyrmkings_due | `malachar` | the Ashen Throne, the Throne of Ash |

Both joins are live and both are wanted. The id is the explicit one and
`loot.test.mjs` checks every id against the live roster, so a rename over there
fails here rather than quietly dropping nothing. The NAME is the second, matched
case insensitively past a leading "the" and any punctuation, and only ever on a
row with `boss: true`; it is what made the feature real before M2 landed and it
is what will catch a boss row written tomorrow.

Seven bosses carry no signature and are not meant to: the four older ones
(`ashenKing`, `motherOfSpiders`, `wardenOfTheCut`, `drownedKnight`), the
Librarian in the Buried Library, and the two wandering bosses. If M2 wants the
Ember Wastes' second dungeon or a wandering boss to leave something named, it
is one row in `SIGNATURES` and nothing else.

## 5. Where the words are

`loot_drops.describeItem` now returns `item.uniqueName` before anything else,
so a sack reads "a sack: Caradoc's Drowned Ring and 1,240 gold" rather than "a
ring". `affixes.identify` rewrites `item.name` and never touches `uniqueName`,
so it survives being read.

The pack window, the tooltip and the paper doll are not this agent's files and
still call the item a Ring. One line in each, wherever they build a label:

```js
  const label = item.uniqueName || nameFor(item);
```

and `item.flavour` is the line to print under it.

## 6. What was measured

Every number below is printed by `node src/mmo/loot.test.mjs` (201 checks) and
`node src/game/loot_drops.test.mjs` (174 checks), which are green. Nothing here
is read off the code.

**Nothing moved for anyone without a character.**
24,000 unprofiled drops over two tables, six tiers and two Luck values, and
3,000 unprofiled kills counting gold and item together, hash to the digests
taken from `git show HEAD:src/mmo/loot.js` before a line of this was written.
The digests are in the test, so this cannot rot.

**The 60/40, through `loot.rollDrop`.**
10,000 rolls, a warrior's skill sheet against a bandit's table (dagger, rapier,
leather boots, ring; the only one a STR 65 swordsman in studded, ring or chain
uses is the ring): the class coin came up biased on **60.12%** of gear rolls.
The share that LANDS in the profile is **70.25%**, not 60%, because the open
forty draws from the whole table including the ring: `0.6 + 0.4 x 1/4 = 70.00%`
predicted, and the test asserts the arithmetic rather than a band. **This is
worth Fable's eye**: the brief's "58 to 62 percent of gear rolls are in the
profile" is only true when the class's share of a monster's gear is near zero.
Making it literally true would mean drawing the forty from the COMPLEMENT of
the profile, which is not what the brief says and would mean a warrior never
finding a wand at all. The code does what the brief's sentence says; the
measurement reports both numbers.

**The 60/40, through `loot_drops.rollFor`,** which is the join a kill calls:
10,000 bandit kills with a character biased 59.37% of gear rolls, and the
warrior walked off with 6,898 rings against 2,471 without one.

**Materials are untouched.** 10,000 rolls against an orc (axe, battleaxe,
studded breastplate, iron ingot) with and without a profile: 2,502 iron ingots
either way, to the unit, on the hardest case for the claim (the warrior wants
all three pieces of gear, so the coin is biased 60% of the time). The same at
the `rollFor` level against a skeleton warrior: 2,502 reagents either way,
while the longswords underneath moved from 2,491 to 3,228.

**The empty intersection.** 10,000 rolls against a cyclops, whose maul a
swordsman cannot use: 60.85% of gear rolls fell back to the whole table, the
record says "nothing this one carries suits you", and the base histogram is
character for character the unprofiled one. Through `rollFor`, against an ogre:
5,937 of 10,000 fell back and the histogram again matches exactly.

**Both directions.** A mage's profile never contains plate, ring, chain or
studded at any STR, and never a kite shield. A warrior who trains Magery to 95
has magery, meditation and evaluatingIntelligence as their top three, is put in
cloth and leather, is handed a staff and is no longer handed a greatsword; the
opening id is never read. A STR 20 swordsman is offered a shortsword and not a
greatsword, which is the same answer `items.canEquip` gives. A bias of 0 draws
from the shelf zero times and reproduces the unprofiled histogram exactly.

**The boss.** 80.03% of 9,339 gear rolls came off the shelf. `bossRoll`'s new
default `floor: 'rare'` leaves nothing below blue in 4,000 tier 1 rolls, where
the same table rolled once leaves 3,608 of 4,000 below blue; `floor: null`
turns it off again. Honestly reported: at the two tiers that call it in the
game today the default changes nothing, because the weight shift already floors
tier 5 at blue and tier 6 at purple. It is there for the lower tier wandering
semi-bosses of the programme's E2 wave, and it is driven at tier 1 to prove it
works rather than asserted.

**The uniques.** Each of the nine bosses leaves its own at **24.58%** of 10,000
kills. One character killing the same boss 10,000 times gets it exactly once,
and the id is on `character.uniques` afterwards. A character already carrying
all nine ids gets nothing in 20,000 further kills. **840,000 kills** spread over
the 84 monsters that are not bosses leave none at all, and a row carrying a
boss's name but not flagged `boss: true` matches nothing. All nine identify
into the power they were given rather than one `identify` rolled for them, all
nine pass `auditItems`, and two seeds of the same unique differ in their five
ordinary lines.

**Cost.** A profile is worked out in 25.8 microseconds and a biased drop rolls
in 0.7 microseconds, so a kill can afford one per kill and no cache is needed.
