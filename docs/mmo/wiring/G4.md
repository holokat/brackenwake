## 1. The create calls

```js
import { createSkinning } from './skinning.js';
import { createTradeNet } from './trade_net.js';
import { panel as tradePanel } from './win_trade.js';

const skinning = createSkinning({
  monsters,                       // W2's; see section 4 for what it still owes
  inventory,                      // W3's. `add(item)` is the only call made
  progression,                    // W1's. `lesson(skill, difficulty, success, rng)`
  character,                      // for `skills.skinning`, `equipment`, `pack`
  hud, audio, floaters,
  at: () => player.pos,           // where you are standing, for the 3 m rule
  rng: Math.random,
});

const tradeNet = createTradeNet({
  character,                      // gold, name, and the pack the trade moves
  name: character.name,
  channel: TRADE_CHANNEL,         // optional; the default is the right one
  at: () => player.pos,           // the position the hello carries
  now: () => performance.now(),   // optional; the frame clock, for ageing peers
  hud,
});

ctx.tradeNet = tradeNet;          // the Trade panel reads it off `ctx`
tradeNet.onInvite((partner, peer) => {
  hud.log(`${peer?.name || 'somebody'} wants to trade.`);
  windows.open('trade', { partner });        // must open, or the peer is cancelled
});
window.addEventListener('beforeunload', () => tradeNet.close());
```

`windows.register(tradePanel)` is unchanged: the panel is the same object with
the same `id`, `title` and `key`.

## 2. Where the update goes


`tradeNet.update` is cheap: it posts one message a second and walks a map of at
most a handful of peers. `skinning` has no update; it only answers clicks.

## 3. The click routing main.js needs

One line, before `interact.click()` and after the monster test, because a
living monster in front of a body is what you were aiming at:

```js
function onClick(now, nowS) {
  const ray = aim();
  const bag = loot.pick(ray);
  if (bag) return loot.take(bag, takeLoot);
  const who = npcs.click(ray, player.pos);
  if (who && who.npc) return who;
  const st = stations.pick(ray);
  if (st) { /* unchanged */ }
  const mon = monsters.pick(ray);
  if (mon) { /* unchanged: queue a swing */ }

  // -------- new: a body under the cursor, with a knife in hand ---------
  const corpse = skinning.pick(ray) || skinning.nearest(player.pos);
  if (corpse && skinning.canSkin(corpse)) return skinning.skin(corpse, now);

  return interact.click();
}
```

`canSkin(corpse)` is true only when the body is unskinned, carries a hide word
and there is a knife, so a click on a skeleton with a sword in hand still falls
through to `interact.click()` and does not eat the click. A player who wants to
be TOLD why nothing happened calls `skinning.skin(corpse, now)` unconditionally:
every refusal has words. The middle ground, which is what the line above does,
is to answer with the knife only when the knife would do something.

`skinning.labelFor(corpse)` is the hover line ("wolf, not yet skinned").

## 4. What `monsters.js` must expose, and does not

This is the one real blocker, and it is G3's file this wave.

**`monsters.corpsesNear(pos, radius)`** returning records shaped
`{ key, actor, row, pos, skinned }`. `skinning.js` writes `skinned` and
`skinnedAt` on the record it is given and reads nothing else.

**`monsters.pickCorpse(raycaster)`** returning one of the same records, so a
click on a body finds it. Until it exists `skinning.pick` returns null and the
routing above falls back to `skinning.nearest`, which is the 3 m ring.

`skinning.needs()` returns the list of whichever of those two is missing, so
the game can say it out loud rather than looking broken.

**And the linger has to grow.** `CORPSE_LINGER_S` is `DIE_SECONDS + 0.4`, which
is **1.5 seconds**: long enough to topple and no longer. Nothing can be skinned
in 1.5 s, so Skinning is unreachable in the running game until a body stays. A
loot sack lies there for 90 s (`BAG_SECONDS`) and that is the number to match:
a body a player could reach is a body a player could reach. Two shapes both
work and neither is mine to choose:

- one linger, 90 s, for every corpse; or
- the topple as it is for a body with no hide word, and 90 s for one that has
  one, which is `skinWordFor(row)` from `loot_drops.js` and one import.

Until then the skinning suite proves the rules and nobody has skinned anything.

## 5. The trade channel

`TRADE_CHANNEL` is **`brackenwake-trade`**, a `BroadcastChannel` name, so two
tabs of the same origin find each other with no server. Where there is no
`BroadcastChannel` (node, and the tests) `openChannel` falls back to
`createLoopback(name)`, an in-memory hub with the same delivery rules:
everybody but the sender, one microtask later.

The protocol is `{ p, from, to, seq, kind, name, ... }` with kinds `hello`,
`offer`, `accept`, `unaccept`, `cancel`, `complete`. Three classes of message
are thrown away and counted in `net.stats`:

- **stale**: a `seq` not ahead of the last one acted on from that session.
- **stranger**: anything but an `offer` from a session we are not trading with.
  A forged `accept` or `complete` cannot steer or finish somebody else's trade.
- **crossed**: an `accept` whose `ack` is not the revision of the offer we are
  showing, which is what a simultaneous change on both sides produces. The
  answer is to re-send the offer, not to commit a table nobody agreed to.

**Nothing moves until both sides commit.** Each tab runs its own `createTrade`
against its own character document and mirrors the other side, so the items
leave one document and arrive in the other exactly once, on that document's own
`commit`, which only runs with both ticks on. A cancel, a crossed message, a
closed tab or a peer gone silent for `PEER_STALE_MS` (4 s) all end the trade
with everything where it was, because nothing had moved yet. A bare `complete`
from the wire never moves an item: if the peer says it committed and we did
not, the trade is cancelled and said out loud.

`06`'s 4 m: a hello carries name and position, and `net.nearby()` is the peers
within `TRADE_RANGE`. The panel greys the button for anyone further off.

## 6. Hides, and the material stamp

`items.js` gained `hide` (2 stones), `thick_hide` (3) and `scaled_hide` (3) as
stackable materials, plus `skinning_knife` as a tool. There is no fourth
"tanned leather": `ores.js` LEATHERS and `recipes.js` both name exactly these
three, so the hide a wolf gives is the material the tanning rack consumes.

The ids differ by convention and are joined both ways:

| ores.js / recipes.js | items.js base |
| --- | --- |
| `hide` | `hide` |
| `thickHide` | `thick_hide` |
| `scaledHide` | `scaled_hide` |

`LEATHER_BASE` and `LEATHER_MATERIAL` are that table, and `auditHides()` fails
at load if either direction breaks.

**W5's convention is obeyed:** a material stack carries `item.material`, the
`ores.js` id. `makeItem` does not carry one, so `makeHide(word, count, seed)`
in `skinning.js` stamps it, and that is the only place in the game a hide is
made. `win_crafting.js`'s `countMaterial` reads `item.material`, and the test
drives the real `createInventory` and the real `countMaterial` to prove a
tanning rack can see the pile.

**A hide is never in a sack.** `itemBaseFor` now answers for the three words so
the knife can hand one over, and `tableFor` filters `SKINNING_WORDS` out before
the roll, exactly as before. `auditLootWords()` runs at load and throws if any
word in any monster table stops joining; `UNJOINED` is `['scroll']` and is the
list to shorten when a scribe's stock exists.

## 7. Decisions taken, and the ones worth arguing with

**Which bodies skin, and why it is not a rule about families.** The monster
row's own loot words are the source. Read that way, every beast has a hide
word, no construct has one, and no undead has one but the bone dragon, whose
row names `scaledHide` and whose scales are the point of it. That matches
03-ITEMS-LOOT without a second table. `auditSkinnable()` holds the two halves
("every beast", "no construct") and throws if a new row breaks either.

**Difficulty: five per tier.** Invented; no document gives a Skinning number.
A rat is 5 and a hydra 25, so no body is harder than a copper vein.

**The success roll is the crafting roll.** Also not in any document. Rather
than write a second "did the work come off" formula, `chanceFor` imports
`craftChance` from `recipes.js`: `clamp(0.5 + (skill - difficulty) * 0.01,
0.05, 0.98)`. One rule, one place.

**The yield is Mining's shape with a slower step.** `1 + floor((skill -
difficulty) / 25)`, invented. A grandmaster takes four hides off a wolf and one
off a hydra. Mining's step of 15 was tried first and gives seven hides from one
wolf, which is a pile of ore and not an animal.

**A failed roll ruins the hide and the body is done.** The crafting rule read
for a thing there is only one of. It still teaches, at `rollGain`'s half
chance for a failure.

**A hide that does not fit stays on the body.** The one exception to "the body
is done": if `inventory.add` refuses, the `skinned` flag is put back and
nothing is taught, so the work can be done again after something is dropped.
The line says the animal keeps it.

**The knife.** A dagger counts in the main hand. A skinning knife counts
wherever it is carried, because `items.js` gives a tool no slot and putting a
thing with no damage in the weapon hand would reach `actor.js`'s
`weaponFrom(equipment.mainHand)`. That is the pickaxe's arrangement already.
The refusal names both.

**A cut costs a swing's worth of time.** `SKIN_COOLDOWN_MS` is 450, the same
number `interact.js` gives a chop, so a fast double click is one cut.

**The panel opens as a list.** With somebody within 4 m on the channel and no
partner handed over, the Trade window opens showing who is there rather than a
trade with a stub that can never accept. With nobody there it is the stub, as
before, which is honest.

- **34 distinct loot words** across every table. All 34 join to a real base

  tier 0 still drop something in one.
- **The roll, both ways.** Skill 0 against a wolf is 0.4000 and a pinned roll
  of 0.99 ruins the hide; a roll of 0.1 takes it. Skill 100 is capped at 0.98.
- **The yield ladder** against difficulty 10: skill 10 gives 1, 35 gives 2, 60
  gives 3, 100 gives 4.
- **The gates, both directions.** 2.9 m skins and 3.1 m refuses with the
  distance in the line. A dagger skins, a longsword refuses. A wolf skins once
  and the second try says "already skinned". A skeleton says "There is nothing
  to skin on a skeleton" and an iron golem says it is stone and iron.
- **The cooldown, measured.** 12 calls over 12 ms produce 1 cut and 1 attempt;
  two calls 451 ms apart produce 2.
- **The trade, item by item in both documents.** Offer, offer, tick, tick: the
  sword leaves A once and arrives in B once, the bow the other way, 50 gold
  moves, and A still holds the dagger it never offered. Both nets count exactly
  one commit.
- **Every refusal path counted.** A change after one tick unticks both sides. A
  cancel, a `close()` mid-trade and a peer gone silent for 4 s each leave both
  packs exactly as they were. A stale seq, a stranger's accept, a stranger's
  complete, a crossed accept and an older protocol number are each thrown away,
  named, and counted in `stats`.
- **The real pack and the real forge.** The last section of the skinning suite
  drives W3's `createInventory` and W5's `countMaterial` rather than fakes:
  three hides stack into one slot, count as 3 `hide` and 0 `thickHide`, a thick
  hide lands in its own stack, and a second wolf takes the count to 6.

**Not verified, because there is no browser here.** Nobody has clicked a body,

The channel is exercised through `createLoopback`, which delivers to everybody
but the sender one microtask later, the same as the real thing, and the same
`onmessage` path runs; what is untested is the browser's own structured clone
of an item record and the panel's DOM. Fable verifies those.

**And Skinning is unreachable in the running game** until section 4's
