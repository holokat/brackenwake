# V2 wiring: grown trees, boulders and grass

Files owned: `src/world/tree_gen.js` (new), `src/world/grass.js` (new),
`src/world/flora.js`, their `*.test.mjs`, and this note. Nothing else was
touched: `chunks.js`, `tree_edit.js`, `interact.js`, `scene.js` and `main.js`
are as V3, V1 and Fable left them.

The old world grew spheres on cylinders and cones on sticks. It now grows
trees: a tapered trunk that leans and wanders, branches in a phyllotactic
spiral or in whorls, each generation pulled up by light and down by its own
weight, and leaves hung on the outer wood as crossed quads carrying a generated
alpha texture of real leaf silhouettes. Bark, leaves, rock and grass blades are
all generated in code as `DataTexture`s, with albedo, normal and roughness. No
canvas, so every one of those code paths runs in node and is measured by
`npm test` rather than described.

## What did NOT change

The `TreeField` record contract, exactly as `tree_edit.js` defines it.

- A record is still `{ x, z, gy, s, ry, alt, oa, chunk }`.
- `layer.of(t)` still returns `{ x, y, z, s, ry }` or `null`.
- Geometry is baked with the base of the trunk at `(0, 0, 0)` growing up `+y`,
  so `of` returns `y: t.gy` and nothing else has to know anything.
- `chopTree`, `shudder`, `treeCopy`, `breakRock`, `regrowTrees`, `pickTree`,
  `dumpTrees` and the tree editor are untouched and tested against the new
  fields in node: three swings fell an oak, the instance count drops by two,
  `felledUntil` is set, `regrowTrees` puts it back and the instances return.

One field was added to the record: `vi`, the variant index. It is derived from
the record's own position when it is missing, so a record dumped by the tree
editor (which only writes `x, z, gy, s, ry, alt`) and reloaded comes back as
the same tree. A stored `vi` that is out of range for a smaller bake is
repaired rather than trusted. Both directions are tested.

## The shape of a species field

`world:oak` used to be four layers. It is now up to twenty-two:

```
for each detail tier (near, mid, far):
  for each baked geometry at that tier:
    one bark layer   (MeshStandardMaterial, bark + normal + roughness)
    one leaf layer   (alphaTest 0.42, DoubleSide, vertexColors, its own depth material)
```

`of(t)` hands a record to exactly one of them: the geometry its `vi` was born
with, at the tier its distance from the player asks for. Layers nobody chose
cost nothing, because `tree_edit`'s rebuild skips a layer with no parts.

### Detail tiers, and why they exist

A grown fir is 11,400 triangles. A boreal chunk ring holds **3,087 tree
records**, measured. At full detail that is **34.9 M triangles a frame**: not a
forest, a slideshow. So each variant is baked three times off the *same*
skeleton (`growTreeLods`), and a record draws the tier its distance asks for.

| tier | range | radial sides | path points | leaf clusters | bark depth | shadow | raycast |
| --- | --- | --- | --- | --- | --- | --- | --- |
| near | 0 to 55 m | full | full | full | all | casts | pickable |
| mid | 55 to 140 m | 50% | 60% | 40%, bigger sprigs | depth <= 1 | no | no |
| far | 140 m out | 34% | 34% | 5%, much bigger sprigs | trunk only | no | no |

Measured triangles per variant (`node src/world/tree_gen.test.mjs`):

```
species     near       mid      far
oak         8320      2566      390
birch       7194      2238      270
pine       11272      3034      168
fir        11404      3176      186
willow     12312      2842      336
palm        3880      1520      180
sakura      9056      2730      360
dead        1380       104       18
cactus       838       306       44
```

Same forest, same 3,087 trees, with the tiers: **2.58 M triangles**. The test
computes both numbers and fails if the tiers stop earning their keep.

Two more things fall out of the tier a mesh belongs to, both set through the
`tag` hook `tree_edit.js` already calls:

- **Shadows.** Only the near tier sets `castShadow`. A shadow pass over every
  tree in the ring costs as much again as the colour pass, and a shadow cast
  from 300 m away is a pixel. Leaves also get a `customDepthMaterial` with the
  same map and alphaTest, or an alpha-cut canopy casts the shadow of a box.
- **Picking.** The axe reaches six metres, so the mid and far tiers get a no-op
  `raycast`. That takes 5,349 far instances out of every click and lets a click
  on the sky through a distant canopy pass through instead of coming back "too
  far to chop".

Variants also share geometry with distance (`LOD_SHARE = [1, 2, 3]`): six
silhouettes near, three at mid, two far. Five species in view was 123 draw
calls before that and 69 after.

### Re-banding

The tiers are measured from the player, so they go stale as the player walks.
`flora.update` writes the position into a live `centre` object that `of` reads,
and marks the tree fields dirty when the player has moved `REBAND_M` (24 m).
`update` then rebuilds **at most one field per frame**, on the existing
`REBUILD_MS` (200 ms) clock, so a re-banding wave never lands as one hitch.

Measured: a re-band of the whole meadow costs **1.5 ms in the worst frame**,
0.4 ms for the field itself. The test drives it both ways: a step shorter than
`REBAND_M` must not rebuild anything, a step past it must.

## The one thing that still needs wiring

`main.js` line 262 already reads:

```js
if (Number.isFinite(s.grass) && typeof runtime.setGrass === 'function') runtime.setGrass(s.grass);
```

`world_runtime.js` does not export `setGrass`, so the settings window's "Grass
density" slider currently does nothing. **One line, in a file V2 does not own:**

```js
// src/game/world_runtime.js, in the returned object
setGrass(v) { flora.setGrass(v); },
```

`flora.setGrass(0..1)` is written and tested: 0 hides both grass meshes, 0.5
puts back about half the blades (7,874 of 15,734 in the flora suite's meadow). Nothing else needs wiring. In particular:

- The **wind clock** needs no wiring at all. `flora.update(nowMs, x, z)` is
  already called every frame by `world_runtime.updateWorld`, and it calls
  `tickWind(nowMs / 1000)`. Every leaf, every needle and every grass blade
  reads the same `windUniforms.uTime`. `setWindStrength(k)` from `tree_gen.js`
  is there if a storm ever wants it; 0 is dead calm, 1 is a normal breeze.
- The **grass** needs no wiring: `createGrass` is created inside `createFlora`,
  parented to the flora group, so `overworldNodes()` already hides it
  underground and `flora.dispose()` already takes it away.

## What a chunk costs

Draw calls are bounded by the bake, not by the number of trees. Measured on 169
chunks of boreal forest with 3,087 standing trees and 418 boulders:

```
77 draw calls, 2.58 M triangles a frame
```

Broken down, per species present:

| | draw calls |
| --- | --- |
| a tree species, worst case | 22 (6 near + 3 mid + 2 far geometries, times bark and leaves) |
| boulders (`rock`) | up to 5 |
| ore at the cave mouths | up to 5 |
| grass blades and ground cover | 2, always, whatever the blade count |
| stumps | 1, and only while something is felled |

The fields are global rather than per chunk, exactly as before: one `TreeField`
per species for the whole world, chunks push and pull records. So a chunk on
its own costs no draw calls at all; the count is set by how many species are
within the ring.

## Species and biomes

`tree_gen.js` grows nine: oak, birch, pine, fir, willow, palm, sakura, dead,
cactus. Each declares its own tree line and slope limit, so the rule is per
species and not one global `TREE_LINE`: an oak stops at 66 m, a fir climbs to
95, dead wood stands to 110. Conifers above the oak line are counted in the
test, so "the rule is per species" is a measurement.

```
meadow    oak, birch, rock
boreal    pine, fir, rock
desert    palm (only near water), cactus, dead, rock
beach     palm, rock
sakura    sakura, willow (only near water), oak, rock
mountain  fir, dead, rock
snow      fir, rock
ocean     nothing
```

Willows and palms are in `WATER_SPECIES` and will not grow away from water
(`river > 0.05` or ground under 3.2 m). Tested both ways: every willow and palm
placed over a 6,400 chunk sweep stands on wet ground, and the dry desert grows
378 other things and not one palm.

`auditBiomeHarvest()` runs at module load and **throws** if a biome has nothing
to chop, nothing to mine, names a species `tree_gen` has no recipe for, or has
a density row that sums over 1 so its last entries could never roll. Sakura had
no boulders at all before this; the audit is why that was found. The test also
proves it on the ground rather than in the table: it censuses 40 chunks of each
biome and checks that both a tree and a boulder actually got placed.

## Grass

`src/world/grass.js` scatters two instanced layers on 8 m tiles out to 56 m:
blades (two crossed quads, a generated nine-blade tuft sprite) and ground cover
(three crossed quads, a fuller twenty-two blade clump). Wind comes off the same
clock as the leaves. Distance fade is a **scale**, not an opacity: a blade
shrinks into the turf as it approaches the ring edge, so nothing pops and
nothing needs sorting.

Tiles are recycled, not rebuilt. Each tile owns a fixed block of instance
slots; walking one tile refills 12 tiles, not 210. The refill is bounded by a
time budget (`TILE_MS = 0.8`, at most `TILE_BUDGET = 4` tiles) rather than a
fixed count, because a tile of thick meadow costs three times a tile of desert.

Measured, standing in open meadow: 208 of 210 tiles live, **26,201 blades and
clumps** around the player, **two draw calls**, worst steady frame **1.69 ms**,
first frame 3.64 ms because it plans the whole ring, 69 frames to fill it from
cold.

`MAX_TILES` is derived from `RADIUS` and `TILE`, so widening the ring does not
silently leave the far side of it bare: that is a fixed-size buffer with a
capacity, and it is computed rather than guessed.

Every blade asks the field for its own ground, biome, water, river and road. An
earlier version interpolated all of that from a 2 m grid per tile; it put 12
blades in a river, 4 in the open sea, and stood one 75 cm off the ground. The
test now checks every blade sits on the field to the millimetre, and that none
of them is in water or on a road.

`TURF` names every biome in `BIOMES`, and the test fails if a biome is added to
`field.js` without one.

## Stumps

`tree_edit.js` skips a felled record entirely when it rebuilds, so a chopped
tree used to leave bare ground until it regrew minutes later, which reads as a
broken button. `flora.js` now draws the stump itself, outside the `TreeField`
so it is not choppable and is not in the raycast back-index: one instanced
mesh, one draw call, 36 triangles, every species, tinted per instance from the
species' own bark colour and sized from the variant's own trunk radius. The
felled list is re-read every `STUMP_MS` (400 ms), because `chopTree` rebuilds
on its own clock and not on `flora.update`'s.

Tested: felling an oak puts a stump within a centimetre of where it stood,
regrowth takes the stump away again, and a broken boulder leaves none.

## Warming

Growing six variants of a species and rasterising its bark and leaf maps costs
**100 to 185 ms**, measured in node. Paid on the frame a player first walks
into a boreal forest, that is a visible stall. Two things keep it off that
frame:

- Fields are built lazily, so only the four or five species a region uses are
  ever built. The meadow test builds five and reports each one's cost in
  `flora.stats.buildMs`.
- Once the world around the player has settled (nothing dirty, no grass tiles
  waiting) `update` builds one species that is not built yet, in `WARM_ORDER`,
  until they all are. The work is identical; only when it lands changes.

Vertex memory: six variants of one species, all three tiers, is **6.1 MB**.

## One trap worth writing down

`vertexColors: true` on a material whose geometry has no `color` attribute
renders **black**, silently. three defines `USE_COLOR` from the material alone
in the vertex stage, declares `attribute vec3 color`, and WebGL hands an
unbound attribute (0, 0, 0). The grass wants a colour per instance, not per
vertex, so its materials set `vertexColors: false` and let three's
`instancingColor` path define `USE_COLOR` in the fragment stage, which is what
makes `setColorAt` work. Both test files now audit the class rather than the
case: for every mesh either module builds, `material.vertexColors` must match
whether the geometry actually carries a `color` attribute.

## Things V2 knows about and did not do

- `interact.js` `NOUNS` maps a field name's last segment to what to call the
  thing under the cursor. It knows `oak`, `palm`, `cactus`, `sakura`, `rock`
  and `ore`. The five new species (`birch`, `pine`, `fir`, `willow`, `dead`)
  fall through to the generic "tree", which is correct but flat. `spruce` in
  that table is now dead: the world has no spruce. Five lines, in a file V2
  does not own.
- Nothing reads `userData.foliage`, `autumnCol` or `snowAmt` in this fork. They
  are still written on every leaf mesh, as before, so a seasonal pass has
  something to find. The real leaf colour is per-cluster vertex data and a
  season pass would have to tint, not replace.
- LOD changeover is a pop, not a cross fade. At 55 m and 140 m, with the
  re-band only happening every 24 m of walking, it is small; it is not zero.
