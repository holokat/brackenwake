# W4 wiring: abilities, targeting, effects, HUD

Four files, all in `src/game/`: `abilities_runtime.js`, `targeting.js`,
`effects.js`, and the grown `hud.js`. Nothing in `src/mmo/` was touched.
Nobody else's file was touched.

**Time is in seconds.** `abilities.js` writes every cooldown, cast and
duration in seconds, so everything W4 owns takes `now` in seconds on one
monotonic clock. `main.js` should compute it once a frame:

```js
const nowS = performance.now() / 1000;
```

Passing milliseconds would make a six second cooldown last a hundred minutes.
This is the single easiest thing to get wrong in the whole hand-off.

---

## 1. The create calls

In boot order, after `hud`, `player`, `camera`, `input`, and after W1's
`actor` and W2's `combat` and `monsters` exist.

```js
import { createEffects } from './effects.js';
import { createTargeting } from './targeting.js';
import { createAbilities } from './abilities_runtime.js';

const effects = createEffects(sc);

const targeting = createTargeting(sc, input, monsters, {
  self: playerActor,                     // W1's actor, so you cannot target yourself
  hud,                                   // a target change writes one log line
  pos: () => player.pos,
  yaw: () => player.yaw,
  clearOnMiss: true,                     // a left click on bare ground drops the target
});

const abilities = createAbilities({
  character, actor: playerActor, input, combat, monsters, targeting,
  effects, floaters, hud, audio, player, camera, progression,

  // optional, each degrades to a spoken "not wired yet" rather than to silence
  heightAt: (x, z) => runtime.heightAt(x, z),
  allies: () => [playerActor, ...summonsAndParty],
  summon: (creatureId, atPos, meta) => monsters.spawnSummon(creatureId, atPos, meta),
  resurrect: (who) => death.raise(who),
  utility: { transmute, steal, meditate, camp },       // W3 and W5 own these four
  enabled: () => !windows.anyOpen && !shop.isOpen,     // see the key collision below
  recompute: (who) => actorMod.recompute(who),
  rng: Math.random,
});
```

### The key collision main.js has to settle

**Settled, and then removed.** The row was made click only, and T3 has since
taken it off the screen altogether: there is no `TOOLS` list, no `pickTool` and
no `hud.onTool`, and `1` to `4` are the ability bar's outright. Everything in
this section is the record of how it stood before that. See
`docs/mmo/wiring/T3-NO-TOOL-BAR.md`.

`main.js` line 212 binds keys `1` to `4` to the tool row:

```js
for (let i = 0; i < TOOLS.length; i++) if (input.pressed(TOOLS[i].key)) pickTool(TOOLS[i].id);
```

`07-RUNTIME-CONTRACT.md` and `06-ECONOMY-UI.md` give `1 2 3 4 5 6 7 8 9 0 - =`
to the ability bar. Left as it is, one press of `1` swings Power Strike AND
puts the player's bare hands away. `hud.test.mjs` asserts that the contended
keys are exactly `1234` so this cannot drift quietly.

The recommendation, and the reason: **give the twelve keys to the bar and make
the tool row click-only.** The tool row is a farm holdover, `hud.onTool` is
already wired, and `interact.js` and `shop.js` only ever call `setTool`, never
a key. One line deleted from `main.js` settles it. If the tools are to keep
keys, `shift+1` to `shift+4` is the other option, and then `enabled` above is
not needed for this reason (it is still wanted for open windows).

Until it is settled, pass `enabled: () => false` to keep the bar quiet, or
delete the tool key loop. Do not leave both listening.

## 2. The frame

The order below is not arrangeable. Two constraints:

- **`effects.update` must come after `player.update`.** `player.update` calls
  `poseCharacter`, which overwrites every rotation on the rig each frame. The
  swing, cast, flinch and death clips ADD to what the gait wrote, so an
  `effects.update` before it is thrown away and the arm never moves.
- **`abilities.update` must come after `monsters.update` and
  `combat.update`,** so a monster that died this frame is not still a target
  and a cast broken by damage is broken before it is allowed to land.

```
input.beginFrame
dev or player.update(dt, move, heightAt)
  if (player.landed) {                       // ONE frame only, read after update
    combat.applyFall(playerActor, player.landed.fallMetres);
    abilities.onLanded(nowS, player.landed.fallMetres);   // Leap Slam slams HERE
  }
camera.update
runtime.update
monsters.update(dt)
combat.update(dt, now)
targeting.update(dt)                         // raycast the cursor, click, Tab
abilities.update(dt, nowS)                   // bar keys, casts, cooldowns, buffs, zones
floaters.update(dt)
effects.update(dt)                           // AFTER player.update. See above.
hud.update(dt, view)                         // the view is built below
sc.follow, sc.setDay, render
input.endFrame
```

## 3. The view object for `hud.update`

Built fresh each frame. Every field is optional and a missing one hides its
widget rather than drawing an empty one.

```js
hud.update(dt, {
  actor: playerActor,                        // health/maxHealth, mana/maxMana, stamina/maxStamina
  target: targeting.frame(character),        // null when nothing is targeted
  bar: abilities.barView(nowS),              // always 12 entries, empty slots included
  buffs: abilities.buffsView(nowS),          // { name, kind: 'buff'|'debuff', remaining }
});
```

`targeting.frame(character)` returns
`{ name, health, maxHealth, fraction, tier, colour, step, word, dead }`.
The colour is the tier step relative to the player: grey two tiers or more
below, green one below, yellow level, orange one above, red two or more above.
The player's tier is the best of the eleven skills that fight, capped at 5.
`06-ECONOMY-UI.md` names the five colours and no offsets, so the offsets are
W4's reading and are written out in `targeting.js` under `TIER_STEPS`.

`abilities.barView(now)` returns
`[{ key, ability, cooldownLeft, affordable, casting }]`, twelve long.

Everything the old HUD exported still works unchanged: `toast`,
`setMaterials`, `setCoins`, `setTool`, `onTool`, `setPlace`, `setDev`,
`setHint`, `el`, `dispose`. New: `log(text, kind)`, `lines`, `clearLog`,
`onBar(fn)`, `update(dt, view)`.

The tool row moved from `bottom: 18px` to `bottom: 88px` and the hint from 96
to 148, because the ability bar now sits at the bottom centre. Nothing reads
those positions in code.

## 4. Events main.js must route

| when | call |
| --- | --- |
| the player takes damage, from `combat.update` | `abilities.onDamaged(amount, nowS)` |
| the player lands, `player.landed` is non-null | `abilities.onLanded(nowS, player.landed.fallMetres)` |
| a plain player swing is about to be queued | `abilities.takeNextSwing(nowS)`, merge into the swing opts |
| a skill or stat changed | `abilities.applyPassives()` |
| the player dies | `effects.die(player)`, `abilities.dispose()` |
| a monster dies | `effects.die(monsterRig)`; targeting drops it by itself |
| any actor is struck | `effects.flinch(rig)` |

`onDamaged` returns `{ interrupted, chance, reason }`. It breaks a rooted cast
per `abilities.interruptRule` when the blow is over a tenth of max health, and
Focus is the saving throw. A **bandage is the exception the document writes in
words**: any damage at all ends it, with no threshold and no roll.

`onLanded` is what makes Leap Slam work. The leap defers the rest of its combo
and the slam fires where the player comes down, not where the key was pressed.
Calling it on a frame with no leap in flight returns `null` and does nothing,
so it is safe to call unconditionally.

## 5. What W2's `combat.js` is called with

Both calls take one extra `opts` argument that a plain swing can leave off.

```js
combat.queueSwing(attacker, defender, {
  abilityId, name,
  multiplier,          // 1.6 for Power Strike, 0.8 for each Whirlwind hit
  hitBonus,            // added to hit chance, 0..1
  ignoreARFraction,    // 0..1, Piercing Arrow
  pierceTargets,       // bodies the shot passes through
  shots,               // Double Shot queues two
  jumpAttack,          // true while airborne; combat_rules applies JUMP_ATTACK_MULT
  immediate,           // an ability ignores the swing timer
  aoe,                 // this hit came out of an area effect
});

combat.queueSpell(caster, { id, name, base: [min, max], damageType, line, vs }, target, {
  abilityId, name, aoe, chain,
});
```

`base` and `damageType` are exactly what `combat_rules.resolveSpell` wants.
The runtime does not apply the spell damage formula itself; `resolveSpell`
owns it.

What W4 needs from W2's `monsters.js`, all optional and all degrading rather
than throwing:

| call | used for |
| --- | --- |
| `targets()` | every area effect, the cone, Tab cycling |
| `pick(raycaster)` | the cursor target |
| `nearestHostile(pos, yaw, range, halfAngle)` | preferred over the local cone when present |
| `push(monster, x, z)` | knockback; falls back to writing `pos` directly |
| `dropAggro(monster, by)` | Peace, Vanish, Hide |
| `corpsesNear(pos, range)` | Raise Skeleton, Corpse Explosion |
| `removeCorpse(corpse)` | Corpse Explosion consumes it |

`halfAngle` is RADIANS from the facing, and forward is `(sin yaw, cos yaw)`,
which is what `stepPlayer` writes.

## 6. Data W4 writes onto actors, for combat and monsters to read

None of it is hidden state; all of it is plain fields, so a resolver can read
it without asking this module anything.

| field | written by | shape |
| --- | --- | --- |
| `actor.buffs` | buff, debuff | `[{ id, abilityId, name, kind, until, effect, mods, stats }]` |
| `actor.status[k]` | control | `{ until, level, source, breakOnDamage }`, k in stun root slow sleep fear silence disarm pacify provoke pull |
| `actor.dots` | dot | `[{ perSecond, until, type, source }]` |
| `actor.absorb` | absorb | `{ source, ratio, until }`, Mana Shield |
| `actor.enchant` | weaponEnchant | `{ damageType, until, hitsLeft, vs, mult, level }` |
| `actor.hidden` | stealth | `{ since, requiresStill, movementNeedsSkill }` |
| `actor.leech` | leech | `{ fraction, of, until }` |
| `actor.marks` | mark | `[{ damageTakenMult, until, from, preventsHide }]` |
| `actor.passives` | passiveMod | `{ [abilityId]: mods }`, refreshed by `applyPassives()` |
| `actor.meditating` | utility | `{ since, manaRegenMult }` |
| `monster.provokedAt` | control provoke | another monster |

Expiry runs in `abilities.update` and calls `recompute` when a buff drops, so
the pools follow the bonus off as well as on.

## 7. `window.__bw`

Add four keys:

```js
window.__bw = {
  ...existing,
  abilities,      // use(slot, now), useById(id, now), barView, buffsView, casting, cooldowns
  targeting,      // current, hover, acquire, set, clear, frame
  effects,        // bolt, burst, ring, column, swing, cast, flinch, die, colourFor
  // hud already exposed; it now also has log, update, onBar
};
```

Useful from the console: `__bw.abilities.useById('fireball', performance.now()/1000)`,
`__bw.targeting.current`, `__bw.effects.swing(__bw.player)`.

## 8. What is not wired, and says so

Four utility actions have no code behind them yet and are hooks on
`createAbilities`: `transmute`, `steal`, `meditate` (this one has a local
implementation), `camp`. Pressing one without the hook writes a line saying
which code is missing rather than eating the cost silently.

`resurrect` and `summon` are the same: without the hook the ability says what
would have happened and who has to build it.

**Sound.** `audio.js`'s `CUES` has no spell, no cast and no buff. The three
cues used here are the ones that exist and honestly fit: `denied` for every
refusal, `bowShot` for an archery ability, `land` for a leap or dash landing.
Everything else is silent on purpose. `docs/sfx-wishlist.txt` is where a spell
cue would be asked for.
