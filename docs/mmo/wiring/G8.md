# G8 wiring: the spell that waits, and the mushroom that goes

Two things the user asked for, and one of them turned out to be two bugs:

> "When casting a spell, if a target is selected the spell casts at it, unless
> it is an area of effect spell. If the target is not selected I should have
> some sort of cursor to indicate who to select as my target for my precast
> spell."

> "When an item is foraged, it should disappear, we already picked it."

Files owned and changed:

| file | what changed |
| --- | --- |
| `src/game/abilities_runtime.js` | the held spell: `pending`, `cursor`, `onTargetPicked`, `cancelPending`, the facing on cast, the range refusal |
| `src/game/targeting.js` | `acquire` and `pickTarget` now tell "too far" apart from "nobody there" |
| `src/world/forage.js` | one clock at the door, and a pick that hides its own instance the same frame |
| the three matching `*.test.mjs` | 446 checks between them, all green |

Nothing else was touched. `main.js`, `foraging.js`, `effects.js` and `hud.js`
are read only here and need the three lines in section 4.

## 1. The spell held on the cursor

### What happens now, in order

1. You press a bar key for a single target spell.
2. `canUse` runs first, so "not enough mana" and "still cooling" still win: a
   spell you cannot cast never gets as far as asking who it is for.
3. `acquire` looks for a target, in the order it always did: the one you chose,
   then the one under the cursor, then the nearest in the cone in front.
4. **Found one, in reach:** it casts, exactly as before, and the player turns to
   face it.
5. **You chose one and it is out of reach:** refused, with the distance and the
   reach in metres and "Walk closer". It does NOT wait, because you already
   said who you meant.
6. **Nobody at all:** the spell is held on the cursor. Nothing is paid, no
   cooldown starts, the ground ring is hidden, the cursor becomes a crosshair,
   and the log reads *"Choose a target for Fireball. Click one, or press Escape
   to let it go."*

The held spell ends in one of five ways, each with a line of its own:

| ending | line |
| --- | --- |
| a click on a valid target in reach | it casts, and pays then |
| a click on bare ground | "... is no longer waiting for a target: you clicked bare ground." |
| a click on a corpse or a townsman | "... : Bones is not something Fireball can be aimed at." |
| a click on one too far off | "... : Far Skeleton is 40.0 m away and the reach is 20 m." |
| Escape, another ability, or six seconds | "... : you changed your mind / you reached for Lightning instead / nothing was chosen in 6 seconds." |
| the same key pressed again | "... : you pressed it again." The key is a toggle, so the spell is put down rather than picked straight back up. |

### Which abilities can wait, counted rather than guessed

`abilities_runtime.test.mjs` presses all 78 in an empty world and counts what
waits. **24 of 78**, and they are exactly the enemy-target rows that are not
armed swings:

| target | n | waits? | why |
| --- | --- | --- | --- |
| `enemy` | 29 | 24 | the five that do not carry `effect.nextSwing`: they arm the NEXT swing and want nobody in particular at the moment of the press |
| `ground` | 11 | no | area and ground both. The ground ring under the cursor already says where it will land, and asking for a second click for a Meteor is worse, not better. **This is the user's "unless it is an area of effect spell".** |
| `self` | 29 | no | including Whirlwind and Frost Nova, which are area effects centred on you |
| `corpse` | 2 | no | Raise Skeleton and Corpse Explosion each find their own corpse and each says so when there is none, so there is nothing to choose |
| `ally` | 7 | no | they fall back to YOU when nothing friendly is selected, so they never reach "no target". A heal with nobody chosen is a heal on yourself, which is what it was before this and what it should stay until there is a party to heal |

The brief asked for `ally` and `corpse` to be able to wait too. They are wired
through the same gate and would wait the moment either stopped having an
answer of its own; today neither ever reaches the "nobody" branch, and the
numbers above are the reason rather than an oversight.

### `PENDING_SECONDS = 6`

INVENTED; no document names a number. It is exported so the test drives the
exact second (5.999 still waiting, 6.000 lapses) rather than a feeling.

## 2. What `abilities` now exposes

```js
abilities.pending          // { ability, slot, startedAt } or null
abilities.cursor           // 'crosshair' while pending, '' otherwise
abilities.onTargetPicked(hit, nowS)   // the click that answers "who?"
abilities.cancelPending(why)          // let it go, out loud
abilities.faceTowards(target)         // turn to face; true if it could
abilities.delayed          // <- WAS `abilities.pending`
```

**`abilities.pending` changed meaning.** It used to be the array of delayed
effects (Meteor's fall, Volley's rain); that is `abilities.delayed` now. They
were never the same thing and one word for both would have read as if they
were. Only `abilities_runtime.test.mjs` was reading the old name, and it was
moved with it.

`onTargetPicked` returns `null` when nothing is held, so main.js may call it on
every click without asking first. `hit` may be a monster record (its `.actor`
is taken), an actor, or `null` for bare ground.

## 3. Range and facing

**Range.** `targeting.acquire` no longer silently swaps a chosen target you
cannot reach for a nearer one. It returns `{ target: null, outOfRange: true,
blocked, dist, reason }` with the distance and the reach in the words, and
`pickTarget` does the same for a cursor hit past the reach. The runtime uses
that flag to tell a distance to walk from a question to ask.

**Facing.** `faceTowards` writes `player.state.yaw` and mirrors it onto
`player.group.rotation.y`, before the cast starts, so a 2.5 s Meteor is aimed
from its first frame.

It does NOT write `player.yaw`: that is a getter with no setter on
`createPlayer`'s api, and assigning to it throws in a module. `player.state` is
the object the getter reads and the object `player.update` writes
`group.rotation.y` from, so writing there is writing the same number the rest
of the game reads. `stepPlayer` only takes the yaw back when the player is
really walking (speed over 0.15), so a standing cast keeps the facing it chose.
Measured at all four compass points, through both the immediate path and the
held path.

## 4. What main.js has to do. Three lines.

### a. the cursor, in `updateCursor`

```js
    function updateCursor(now) {
      if (now - cursorAt < 100 || dev.on || windows.anyOpen) return;
      cursorAt = now;
      const ray = aim();
      let want = abilities.cursor;          // <- ADD. A held spell owns the cursor.
      if (!want) {
        if (loot.pick(ray)) want = 'grab';
        ...
      }
      if (want !== cursorNow) { cursorNow = want; sc.renderer.domElement.style.cursor = want; }
    }
```

The 100 ms throttle already in that function means the crosshair can appear or
clear up to a tenth of a second late. That is the existing behaviour of every
cursor in the game and was not changed.

### b. the click, at the TOP of `onClick`

Before the loot sack, before the NPC, before the mushroom, before the monster:
a click while a spell is held is an answer to a question, not a grab and not
the start of a fight.

```js
    function onClick(now, nowS) {
      const ray = aim();
      // a held spell owns the click: it is choosing who, not starting a fight
      if (abilities.pending) {
        const mon = monsters.pick(ray);
        return abilities.onTargetPicked(mon || null, nowS);
      }
      const bag = loot.pick(ray);
      ...
```

`onTargetPicked` sets the chosen one as `targeting.current` itself, so the
target frame at the top of the screen follows without a second call.

### c. Escape

`abilities.update` already reads `input.pressed('escape')` and cancels, whatever
`enabled()` says, because a held spell owns the cursor even with a window up.
So Escape works with no line in main.js.

**But it also opens Settings on the same press, and that is a wart this agent
could not fix from inside its own files.** `windows.update(dt)` reads Escape
itself at main.js line 856, after `abilities.update` at line 816, and
`input.js` has no way to swallow a key once it is in `fresh`. The measured
consequence: one Escape with a spell held cancels the spell AND opens the
settings panel, and the player presses Escape again to close it. Both actions
announce themselves, so nothing is silent, but it is one press doing two
things.

The one-line fix belongs to whoever owns `windows.js` or `input.js`:

```js
// windows.js update(dt, opts): let a caller say the key is already spoken for
if (input.pressed(ESCAPE_KEY) && !opts?.escapeTaken) escape();
// main.js
windows.update(dt, { escapeTaken: escapeWentToAbilities });
```

or an `input.consume(key)` that deletes from `fresh`, which would settle this
class of collision rather than this one instance of it.

### d. the HUD, if it wants to light the held cell

`hud.js` is nobody's file this wave. One line in `drawBar` would show which
spell is waiting:

```js
c.el.className = 'cell' + (e.casting ? ' casting' : '') + (e.unusable ? ' unusable' : '')
  + (abilities.pending?.slot === i ? ' waiting' : '');
```

Nothing depends on it; the log line already names the spell.

## 5. The forage bug was two bugs

The user's report was "when an item is foraged, it should disappear". It never
did. Reproduced before anything was written, with main.js's own pair of calls:

```
after remove   count 1292 of 1293   harvestedUntil 1122000
after update   count 1293 of 1293   harvestedUntil 0        <- back already
```

### Bug one: two clocks

main.js hands `foraging.harvest` the requestAnimationFrame stamp
(`performance.now()`, about 42,000 forty two seconds into a session) and hands
`forage.update` no clock at all, so regrowth ran on `Date.now()`, about
1.79e12. A chanterelle picked at 42,000 was stamped to grow back at 1,122,000,
and the very next `update` **in the same frame** read 1.79e12 >= 1,122,000,
grew it back and redrew it. The pack got the mushroom and the mushroom never
left the wood.

The field now owns one clock (`opts.now`, `Date.now` by default) and every
`now` handed in at the door goes through one function. A reading on the field's
own clock is used exactly as given. A reading from elsewhere is not refused,
which would throw away the caller's intended elapsed time: it is **translated**.
The field learns the offset the first time it sees a foreign clock by pinning
that reading to its own reading of the same instant, and applies it thereafter.
So a caller who picks at 42,000 and asks again at 43,000 gets one second, and
it is one second on the clock the regrowth sweep uses.

`stats.foreignClock` counts the translations, so the miswiring stays visible.
**It reads 1 per pick in the game today.** The tidier fix is one character in
main.js:

```js
        const r = foraging.harvest(pickF.rec, now);      // now is performance.now()
        const r = foraging.harvest(pickF.rec);           // <- foraging's own clock is Date.now()
```

That would also fix `foraging.js`'s "about N minutes to grow back" line, which
subtracts a wall-clock stamp from a page-clock `now` and would say about
29 million minutes if a player ever reached it. Today nothing can: `pick` and
`nearest` both skip a harvested record, so a picked patch cannot be clicked
again. It is a loaded gun with the safety on, and it is in `foraging.js`, which
G8 does not own.

### Bug two: the whole chunk was rebuilt to hide one mushroom

`remove` called `drawChunk`, which threw away and rebuilt every InstancedMesh
in the chunk. It did hide the record, but it cost a chunk rebuild per pick.
Measured, 200 picks in one 3x3 ring of 107 meshes:

```
old   200 picks in 18.6 ms  (0.093 ms each), 209 rebuilds
new   200 picks in  1.2 ms  (0.006 ms each),   9 rebuilds   (the 9 are the chunks loading)
```

`drawChunk` now gives every record of a kind an instance slot, live ones first,
and sets `im.count` to how many are standing. A pick swaps the record's slot
with the last live slot and takes the count down by one; regrowth does the same
move backwards. Three's `InstancedMesh` honours `count` in both `raycast` and
`computeBoundingSphere`, so a hidden slot is neither drawn nor picked, the same
frame. `drawChunk` is now only the fallback for a record whose mesh has been
rebuilt without it.

`drawCalls` now counts only meshes with `count > 0`, because three's buffer
renderer returns before issuing a draw for an instance count of zero. A chunk
whose whole kind has been picked used to be counted as a draw call it was not
making.

### Also worth one line from whoever owns main.js

`forage.update(px, pz, season)` may now be given a fourth argument, `now`, and
it will be believed if it is on the same clock. main.js passes three, which is
correct and needs no change.

## 6. What was measured

`node src/game/abilities_runtime.test.mjs` 209 checks, `targeting.test.mjs` 57,
`world/forage.test.mjs` 180. All green. Every gate driven both ways:

- Fireball with a skeleton BEHIND the player waits, and holds `{ fireball, slot
  0, startedAt 0 }`; with one in front it casts at once and holds nothing.
- Holding it leaves mana at **200 of 200** and `cooldownLeft` at 0.
- The click pays **once**: 200 to 191, which is Fireball's 9, and the cooldown
  starts at the click (3 s left at t = 0.5) and not at the press.
- Escape leaves mana at 200 and stamina at 200: there is nothing to refund
  because nothing was paid.
- A quiet frame does not put it down; at 5.999 s it is still held; at exactly
  6.000 s it lapses, saying "nothing was chosen in 6 seconds".
- Pressing Lightning while Fireball waits says "Fireball is no longer waiting
  for a target: you reached for Lightning instead", and Lightning is then the
  one waiting.
- Clicking a target 40 m off with a 20 m spell says "40.0 m away and the reach
  is 20 m" and costs nothing; clicking a corpse says which corpse.
- Meteor (ground, area) never waits and draws the ground ring; Whirlwind (self,
  area), Battle Cry (self buff), Heal (ally) and Power Strike (armed swing)
  never wait.
- All 78 pressed in an empty world: exactly 24 wait, which is exactly the enemy
  rows without `nextSwing`.
- A CHOSEN target 40 m off refuses with the distance, does not wait, and takes
  no mana.
- Facing: north, east, south and west, one through the immediate path and three
  through the held path, every yaw exact to 1e-9. A self buff does not spin the
  player round.
- Forage: the mesh drops from 41 instances to 40 on the pick with **0 rebuilds**,
  the ray no longer finds the record, and both come back at eighteen minutes,
  again with 0 rebuilds. Picking all 41 of a kind leaves `count` 0 and takes the
  ring's draw calls from 107 to 106.
- The two clocks, both ways: a page-clock stamp is translated and counted in
  `stats.foreignClock`, the same frame does not grow it back, a page-clock
  caller still gets its own eighteen minutes, and a reading on the field's own
  clock is used to the millisecond with nothing counted as foreign.

## 7. Not verified, and one thing that went wrong

- **Nothing here has been run in a browser.** No player has seen a crosshair or
  a mushroom vanish. Fable verifies.
- **Section 4a and 4b are not wired.** Until those two lines go into main.js the
  cursor never changes and a click while a spell is held goes to the loot sack,
  the mushroom or the monster as it always did, which means the held spell can
  only be ended by Escape, another key or the six second lapse. The runtime is
  live either way: pressing a spell with nobody in reach already says "Choose a
  target" instead of refusing.
- **The Escape collision in 4c is real and unfixed.** It is measured only by
  reading the frame order in main.js (816 before 856) and `input.js`'s lack of a
  consume, not by watching it happen.
- `npm test` on this machine has **suites failing that are nothing to do with
  this work**, and every one of them is a wall-clock budget on a machine running
  several agents and suites at once. Three runs during this work gave three
  different sets: `win_map` (an 8 km map draw measured at 218 ms in one run and
  436.7 ms in the next, against a 100 ms budget), `chunks` (a build frame at
  33 ms against 16 ms), `flora` (a warming frame at 376 ms then 398 ms against
  120 ms), `field` (5.6 us a sample against 4 us), and `dungeon` in the first
  run only, which another agent had fixed by the third. The last run reports
  **3 SUITE(S) FAILED** and not one of them is a file G8 owns. `win_map`,
  `chunks` and `flora` were each confirmed failing in a clean
  `git worktree add --detach <tmp> HEAD` with none of these changes in it, so
  they pre-date this work, and the numbers moving between runs is the proof
  that they are load rather than logic.
- **The three suites G8 owns are green run on their own**: 209, 57 and 180
  checks.
- **A mistake worth writing down: do not `git stash` in this working tree.**
  Several agents share it. A `git stash push` to check whether those failures
  pre-existed reverted every agent's uncommitted work at once, and the `pop`
  then aborted because another agent had written to two of the files in the
  meantime. Everything was recovered (`git checkout stash@{0} -- .`, verified
  file by file against the stash, zero mismatches, stash dropped), and the
  pre-existing `stash@{0}` from before this session was not touched. The safe
  way to test a clean tree is `git worktree add --detach <tmp> HEAD`, which is
  what the check above finally used.
