# Z1: the world is bounded, and it has twenty one named places in it

Design note: `docs/mmo/09-WORLD-ZONES.md`. Read that first; this file is only
the list of calls other people's files have to make.

Owned and changed: `src/world/zones.js` (new), `src/world/field.js`,
`src/world/sites.js`, `src/world/sitegrid.js`, `src/game/win_map.js`,
`src/game/compass.js` (new), their tests, and the two documents.

Changed outside that list, and why, so it can be reviewed: five test files
surveyed the world past 8 km and were measuring the ring ocean. See the last
section.

## 1. main.js

### 1.1 The compass

```js
import { createCompass } from './compass.js';

const compass = createCompass(hudRoot, { player, camera, character });
// once a frame, wherever hud.update is called
compass.update();
// on teardown
compass.dispose();
```

It sits at `top: 38px`, centred, which is under `#bw-place` and above
`#bw-target`. If U4's HUD work moves the place plate, move `#bw-compass`'s `top`
with it; it is one line in `compass.js`'s CSS.

It reads `camera.forwardYaw` in preference to `player.yaw`, because the strip
should follow where you are looking and in third person the camera turns before
the body does. It reads `character.waypoint` and writes nothing.

`compass.setShown(false)` hides the strip, for the settings window.

### 1.2 The waypoint is part of the character document

`win_map.js` writes `character.waypoint = { x, z, name }` on a click and calls
`state.touch('waypoint')`. For that to survive a reload, `state.js` has to carry
`waypoint` (default `null`) and `zones` (default `[]`) on the character. Neither
is mine.

### 1.3 Zone discovery: a banner and a saved id

Alongside the existing `runtime.onDiscover`:

```js
import { zoneSub } from '../world/zones.js';

runtime.onZone((zone) => {
  hud.zone(zone.name, zoneSub(zone));      // "QUIET COUNTRY", "VERY DANGEROUS"
  hud.toast(zone.line);                    // the authored sentence
  if (Array.isArray(character.zones) && !character.zones.includes(zone.id)) {
    character.zones.push(zone.id);
    state.touch('zones');
  }
  audio.play('discover');
});
```

Use `zoneSub(zone)`, NOT `zone.line`, for the banner's second line: `hud.zone`
renders it at 13px, uppercase, `letter-spacing: .3em`, which is a slot for three
or four words. `zone.line` is a whole sentence and belongs in the toast. It
fires ONCE per zone per character, ever.

### 1.4 The place plate

`main.js` currently falls back to `BIOME_NAMES[sample.biome]` when no site is
near. A named region is a better answer than "meadow":

```js
const zone = runtime.discovery.zoneNow(p.x, p.z);
if (best) text = best.name;
else if (zone) text = zone.name;
else text = BIOME_NAMES[sample.biome] || sample.biome;
```

### 1.5 The world's edge

The ground at 8 km is the ocean floor at -30 m, and a player who keeps walking
walks along it under the water. Nothing stops them today. If you want them
stopped:

```js
import { clampToWorld } from '../world/zones.js';
const c = clampToWorld(next.x, next.z);       // free when already inside
if (c.moved) { next.x = c.x; next.z = c.z; hud.toast('the sea, and no way across it'); }
```

`insideWorld(x, z)` is there for a cheaper yes or no.

## 2. world_runtime.js

### 2.1 Fire the zone event

`createDiscovery` now returns `checkZone(x, z, nowMs)` and `zoneNow(x, z)`.
`checkZone` is throttled to 400 ms exactly like `check`, so calling it every
frame is free. In `updateWorld`, beside the existing discovery call:

```js
const zone = discovery.checkZone(x, z, nowMs);
if (zone && zoneFn) { try { zoneFn(zone); } catch (err) { console.warn('onZone threw', err); } }
```

and expose `onZone(fn)` next to `onDiscover(fn)`.

### 2.2 Let a player into a mine

A mine is `site.kind === 'mine'`. It is NOT enterable itself: its `mouths` are.
Each mouth is already a complete, cave shaped site object, so `enterDungeon`
takes one with no change at all:

```js
{ id: 'z:ironshoulder:0#m1', mine: 'z:ironshoulder:0', zone: 'ironshoulder',
  kind: 'cave', authored: true,
  cx, cz,                 // its own generator cell: two cuts are never one level twice
  x, z, y, flatR: 6,
  facing,                 // it opens back down toward the yard
  name: 'the Deep Shoulder, the second cut',
  article: 'a mine mouth',
  oreBand: ['iron', 'silver', 'coldiron'] }
```

Two things have to happen for a player to use one:

1. **`site_models.js` has to build the mouths** and set `userData.site = mouth`
   on their meshes, so `world_runtime.pick` returns the mouth rather than the
   mine. Today `buildSiteMarker` has no `mine` branch and a mine renders as an
   empty group.
2. **`enterDungeon` needs no change**, because a mouth already says
   `kind: 'cave'`. If you would rather guard it, the check is
   `site.kind === 'cave' || site.kind === 'dungeon'`, which it already is.

`sites.mouthsNear(field, x, z, r)` is exported from `src/world/sites.js` and
returns every mouth near a point, for a proximity based "press E to go in".

## 3. dungeon_gen.js

**One thing, and it is the whole point of the mines.**

`generateDungeon(seed, site, level)` should read `site.oreBand` when it is
present and put it on the layout, then draw each ore cell's tier from it:

```js
layout.oreBand = site.oreBand || null;
// where the cave branch tags an ore cell:
const tier = layout.oreBand
  ? layout.oreBand[hash2(gx, gz, seed) % layout.oreBand.length]
  : null;                    // null means "as before": veinsFor(kind, depth)
layout.ore.push({ gx, gz, ore: tier });
```

`site.oreBand` is set by `field.siteInCell` on **every** cave and every mine, so
a rolled cave gets one too: the band of the zone it stands in, which outside a
mine zone is `['copper', 'tin', 'iron']` and nothing richer. Falling back to
`veinsFor` when it is absent keeps every existing call site working.

Without this change a cut behind the Sallow Fall, which the world says is
voidrock and starfall, generates exactly the same ore as a cut behind the
Millrun Adit. The band is on the site and nothing reads it yet.

## 4. monsters.js

**One line.** `field.sampleAt(x, z)` now returns `danger`, a frozen `[lo, hi]`
of monster tiers, on every sample. It is never null: ground no zone claims gets
a band by its distance from the origin, 1 to 1 at home rising to 4 to 5 at the
rim.

```js
const s = field.sampleAt(x, z);
const [lo, hi] = s.danger;          // roll the spawn's tier in this band
```

`HABITAT[s.biome]` still says WHAT lives there; `s.danger` says how hard it is.
The same sample also carries `zone`, the zone's id or null, if a roster ever
wants to be zone specific (a named boss in The Stone Garden, say).

The array is shared and frozen: do not mutate it, and do not worry about the
allocation, because there is not one.

## 5. flora.js

`flora.js` already scatters ore boulders in a ring round a cave mouth
(`ORE_RING`, `ORE_COUNT`, gated on `st.kind !== 'cave'`). A mine's surface seams
want the same treatment, and they come with their positions and their tiers
already worked out:

```js
for (const st of sites) {
  if (st.kind === 'mine' && st.seams) {
    for (const sm of st.seams) {
      if (sm.x < x0 || sm.x >= x0 + CHUNK || sm.z < z0 || sm.z >= z0 + CHUNK) continue;
      (out.ore ||= []).push({ x: sm.x, z: sm.z, gy: sm.y - 0.2, ore: true, tier: sm.ore, /* ...as the cave ring does... */ });
    }
    continue;
  }
  if (st.kind !== 'cave') continue;
  // ...unchanged...
}
```

Until that lands, a mine's seams exist in the data and no player will ever see
one. `zones.test.mjs` proves each seam carries an ore id from its own zone's
band and lies on the levelled yard within 1.2 m; it cannot prove anybody drew it.

Nothing else in flora needs telling: the yard's `flatR` of 20 already clears
itself of trees, because `clearingOf` reads `flatR`, and fauna's `siteClear`
does the same.

## 6. win_dev.js: a name collision worth knowing about

`win_dev.js` exports `zoneSearch`, which hunts outward for a chunk of each
BIOME. That is not this "zone". Nothing breaks, but if the dev bench grows a
"take me to a region" button it should read `ZONES` from `src/world/zones.js`
and not `zoneSearch`.

## 7. The tests changed outside Z1's ownership

The bounded world broke one class of test: **anything that surveyed the world
past 8 km was measuring the ring ocean**. Five files, and the fix in each is the
survey range, not the thing under test. Every edit is commented in place and
names `src/world/zones.js`.

| file | was | now |
| --- | --- | --- |
| `src/world/sitegrid.test.mjs` (mine) | cells -30..30, 14.4 km | cells -17..17, the world |
| `src/world/roads.test.mjs` | cells -25..25, 12 km | cells -16..16, 7.7 km |
| `src/world/fauna.test.mjs` | 400 chunks in a line east, 25.6 km | a 20 by 20 block, 1.28 km square |
| `src/game/win_dev.test.mjs` | four probes at 10, 32, 141 and 89 km | four inside the continent |
| `src/world/grass.test.mjs` | a meadow chunk at 12.8 to 20.5 km | one at 3.8 to 7.6 km |

`roads.test.mjs` needed three more changes, and these are judgement calls its
owner should look at. All three were assertions that looked for an EXAMPLE, and
the twelve roads the bounded world holds do not contain one. In each case the
assertion was rewritten to check the PROPERTY over every road instead, which is
stronger, not weaker:

- "a road can be built because the OTHER end picked it" wanted a one way pick.
  All twelve roads were picked by both ends. It now checks the invariant the OR
  actually makes: every road has at least one end that picked the other. The
  one way count is still printed.
- "road falls off from centreline to verge" measured `roads[0]` only, and three
  of the twelve pass within a verge's width of another road, so a hair of that
  road's strength at 3 m failed it depending on which road came first. It now
  measures all twelve, requiring 1 on the centreline and under 0.01 at 3 m.
- "12 m off the road the ground does exceed 0.5" wanted a steep verge somewhere.
  None of the twelve has one. It now checks that the road surface is smoother
  than the ground beside it, which is the claim the grading is really making.

`npm test` is green.
