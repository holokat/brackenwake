# W5 wiring: the people, and five windows

Files owned: `src/game/npcs_runtime.js`, `win_talk.js`, `win_trade.js`,
`win_crafting.js`, `win_map.js`, `win_settings.js`, their `*.test.mjs`, and
this note. Nothing else was touched.

Every panel exports `panel` (and a default export of the same object), matching
`07-RUNTIME-CONTRACT.md` and W3's `windows.js`.

---

## 1. The create calls

```js
import { createNpcs } from './npcs_runtime.js';
import { panel as talkPanel } from './win_talk.js';
import { panel as tradePanel } from './win_trade.js';
import { panel as craftingPanel, STATION_KINDS, stationsForSite } from './win_crafting.js';
import { panel as mapPanel } from './win_map.js';
import { panel as settingsPanel } from './win_settings.js';
import { buildCharacter } from './player.js';

const npcs = createNpcs(sc, runtime, {
  buildCharacter,          // player.js's rig; injected so the test can fake it
  root: hudRoot,           // where the name plates go, the same root floaters uses
  at: state.pos,           // so the town you boot inside has people on frame one
  ctx,                     // needs { hud, audio, windows } for the click
});

windows.register(talkPanel);
windows.register(tradePanel);
windows.register(craftingPanel);
windows.register(mapPanel);
windows.register(settingsPanel);
```

`ctx` is the one object `createWindows(root, input, ctx)` already holds. It has
to carry the fields listed in section 4.

## 2. Where the update goes

One line, after `runtime.update` and before `interact.update`, so the people
are standing on ground the streamer has already built and the plates project
through a camera that has already moved this frame:

```
runtime.update(...)
npcs.update(dt, player.pos, dayFactor)      // <- here
interact.update(dt, nowMs)
```

`dayFactor` is the number already computed for `sc.setDay`. It is optional: with
it, the Necromancer's stall at a ruin is there at night and gone by day, which
is the only thing `npcs.js` says about time. Without it nobody is ever hidden,
and the ruin's stall stands all day.

`windows.update(dt)` already ticks the Map panel, which redraws every 2 s.

## 3. Events main.js has to route

**A click on a person.** Before `interact.click()`, so a person in front of a
house takes the click and not the roof:

```js
const hit = npcs.click(raycaster, player.pos);
if (!hit.npc) interact.click();
```

`click` returns `{ npc, opened, text }`. It opens Talk itself through
`ctx.windows.open('talk', { npc })` when you are within 4 m, and toasts the
distance when you are not. It says nothing at all when the ray found nobody, so
`interact.click()` is free to answer.

`npcs.pick(raycaster)` and `npcs.nearest(pos, r)` are there for hover text: the
HUD can name whoever the cursor is over the same way it names a tree.

**A click on a station.** `win_crafting.js` exports `STATION_KINDS` (the seven,
each with `{ id, name, for, skills, recipes, inHamlet }`) and
`stationsForSite(site)`, which gives the spots for one settlement:
`[{ id, name, site, x, z, yaw }]`. A town gets all seven, a hamlet gets forge,
workbench and kitchen, a ruin gets none. Place a model at each, and on a click
within reach:

```js
ctx.station = 'forge';
windows.open('crafting', { station: 'forge' });
```

The panel reads `extra.station` first and falls back to `ctx.station`. With
neither it says you are not at a station and lists the seven.

**A trade.** `windows.open('trade', { partner })` where `partner` is a
`createStubPartner({ name, gold, slots, items, mind })` today and a remote peer
later. With no partner the panel makes a stub that never accepts, which is
honest: nobody is on the other end yet.

**Death.** Nothing here. The Talk panel's Heal tab reads `character.health <= 0`
or `character.dead` and offers a raise; whoever kills the player sets those.

## 4. `ctx` fields read, and the hooks needed

Read, all optional except `character`:

| field | used for |
| --- | --- |
| `character` | gold, skills, pack, settings, health, `vendorMemory`, `discovered` |
| `inventory` | W3's: `pack` getter, `add(item)`, `remove(index, n)`, `emptySlot()` |
| `actor` | `recompute(actor)` after training or a raise |
| `hud` | `toast(text, kind)` and `log(text, kind)` if it exists |
| `audio` | `play(cue)`, and settings calls `setMusicVolume`, `setSfxVolume`, `toggleMusic`, `toggleSfx`, `musicOn`, `sfxOn` |
| `floaters` | `spawn(pos, text, kind)` for gold, gains, heals and loot |
| `player` | `pos` for floaters, `yaw` for the map arrow |
| `runtime` | `field` for the map, `discovery` as the fallback for discovered sites |
| `windows` | `open(id, extra)`, used by `npcs.click` |
| `progression` | `lesson(character, skillId, difficulty, success, rng)` after a craft |
| `now` | ms, a number or a function. Falls back to `Date.now()` |
| `station` | the station id main.js sets when a station is clicked |
| `rng` | optional; every roll takes one and falls back to `Math.random` |

**Hooks main.js must implement:**

- **`ctx.applySettings(settings)`** is the whole of section 6.
- **`ctx.newCharacter()`** wipes and opens creation. Without it the Settings
  panel says so instead of pretending, and nothing is wiped.
- **`ctx.now()`** should be the frame clock main.js already keeps, so vendor
  memory does not jump when the tab sleeps. `Date.now()` works.

**Audio cues used, all of which exist in `audio.js` CUES:** `buy`, `sell`,
`denied`, `discover`, `pickup`. No new cue was invented.

## 5. `window.__bw` should gain

```js
window.__bw = { ...,
  npcs,                                   // list(), count, pick, nearest, click, at(id)
  panels: { talk: talkPanel, trade: tradePanel, crafting: craftingPanel,
            map: mapPanel, settings: settingsPanel },
};
```

`mapPanel.lastDraw` carries `{ ms, samples, sites, roads, stride }` from the
last redraw, which is how the map's cost is checked in the running game and not
only in node.

## 6. `applySettings(settings)`: every key and what it means

Written to `character.settings`, handed over whole on every change. The table
also lives in `SETTINGS` in `win_settings.js`, and `auditSettings()` fails at
load if a key has no stated meaning.

| key | shape | default | what main.js does |
| --- | --- | --- | --- |
| `music` | 0 to 1 by 0.05 | 0.5 | `audio.setMusicVolume(v)`. The panel already calls it; this is for load |
| `sfx` | 0 to 1 by 0.05 | 0.7 | `audio.setSfxVolume(v)` |
| `musicOn` | on or off | on | `audio.toggleMusic()` until `audio.musicOn` matches |
| `sfxOn` | on or off | on | `audio.toggleSfx()` until `audio.sfxOn` matches |
| `shadows` | on or off | on | `renderer.shadowMap.enabled = v` and `lights.sun.castShadow = v` |
| `ring` | 6, 9 or 12 | 9 | the world stream's ring radius in chunks, and `sc.setFog` to just inside it |
| `pixelRatio` | 1 or `'device'` | device | `renderer.setPixelRatio(v === 'device' ? devicePixelRatio : 1)` then `sc.resize()` |
| `grass` | 0 to 1 by 0.1 | 1 | the flora density multiplier; 0 means no grass |
| `textScale` | 0.6 to 2 by 0.1 | 1 | `createFloaters(sc, root, { textScale: () => character.settings.textScale })` |
| `invertDrag` | on or off | off | the sign of `input.drag.dy` before the camera reads it |
| `sensitivity` | 0.25 to 3 by 0.05 | 1 | the multiplier on `input.drag.dx` and `.dy` |
| `bar` | 12 key strings | `1 2 3 4 5 6 7 8 9 0 - =` | `abilities_runtime` reads `settings.bar[i]` for slot `i` |
| `dev` | on or off | off | `dev.toggle()` until `dev.on` matches |

On load, run `normalise(character.settings)` from `win_settings.js` first: it
fills in what an old save is missing, clamps what is out of range and throws out
what should not be there, so nothing hand edited reaches the renderer.

The Settings panel declares `keys: BAR_KEYS`, so `windows.consumes('3')`
answers true while it is open and pressing 3 during a rebind does not fire an
ability.

## 7. What was found by tracing the path, and what is still open

These are gaps in the pure layer that this pass had to work around. None of them
is mine to fix.

**`items.js` has no base for some things recipes and vendors name.**
`makeItem` throws on an unknown base, so any button offering one would have
exploded. Recorded with reasons in `NO_BASE_FOR` (win_talk.js) and `UNMAKEABLE`
(win_crafting.js), and both files run `makeItem` over every row and every recipe
at load, so a button that throws cannot ship.

Measured on the tables as they stand: **421 of 464 recipes** resolve to a real
item; **43 do not** (4 tools, 4 bags, 35 scrolls). Both counts move on their own
as `items.js` grows: the tool bases appeared while this was being written and
three of the seven tool recipes lit up with no code change. The tests read the
live set, not a frozen list.

**Two spelling mismatches, now bridged in `resultBaseFor`:**
- every armour recipe names the piece (`cloth_hood`); `items.js` names the slot
  (`cloth_head`). Resolved from the recipe's own `armourTier` and `slot`.
- `throwingKnives` against `throwing_knives`.

**A material stack needs `item.material`.** Recipes ask for `iron`, `oak`,
`ginseng`. `items.js` has the stacks `ingot`, `ore`, `log`, `reagent` and no
field saying which metal or which wood. The convention this pass established,
and which mining, lumberjacking, foraging, loot and vendor stock all have to
follow or the forge will say you have no iron while you stand on twenty ingots:

> a material stack carries `item.material`, the `ores.js` id.

`countMaterial` reads that and only counts entries whose base `kind` is
`material`, so a crafted copper dagger is not counted as copper to melt back
down. That was a real bug caught by the test, not a hypothetical.

**Crafted and bought items carry `label`.** A potion of healing and a ration are
both stack bases whose `items.js` name is "Potion" and "Food". The real name is
on `item.label`, and the recipe id on `item.recipe`. W3's `labelOf` should
prefer `item.label` when it is there, or the bag will show twelve rows of
"Potion".

**No recipe carries a gold cost.** `refusalFor` reads `recipe.gold` so the
refusal is written and tested, and it fires for zero of 464 recipes today. The
day `recipes.js` grows a bench fee it lights up on its own.

**`recipes.js` quality formula against 03-ITEMS-LOOT.md.** The module implements
`0.6 + (skill - difficulty) * 0.005 + random(-0.1, 0.1)`; the document now reads
`0.9 + ... + random(-0.2, 0.2)`. The panel shows whatever `craftQuality` really
returns, called with the jitter pinned, so the forecast and the roll can never
disagree. Which of the two is meant is for whoever owns `recipes.js`.

**The vendor hour.** `06` says "in the last hour". A day and night cycle is
`DAY_CYCLE_MS`, 360,000 ms, so an hour of world time is 15 seconds and the rule
would do nothing. `VENDOR_MEMORY_MS` is one hour of play, 3,600,000 ms off
`ctx.now()`. Kept in `character.vendorMemory[siteId][key]` as
`{ bought, sold, at, stock, stockedAt }`, so it saves and loads with everything
else and one town's memory is not another's.

**Measured, and off by one from the brief.** The floor first binds at
`soldThisHour = 18`, which is the **19th** unit sold, not the 18th: at index 17
the rate is 5.0032%, a thousandth of a point above the 5% floor. Buying twenty
raises the twenty first unit to 2.6533 times the first, which is `1.05^20`
exactly. Both numbers are asserted, with the arithmetic printed.

**`sellsToTier`.** `05` says the Blacksmith "sells iron weapons and armour to
tier 3". Read here as the `ores.js` metal ladder, where iron is tier 3, and
applied as a cap on a stock row's `materialTier`. Every row on the shelf today
is tier 3 or below, so the cap filters nothing yet; it is wired so that adding a
mithril longsword row would drop out of the smith's rack on its own.

**Where the people stand.** `sites.js` exposes a site's centre, `flatR` and
`facing`, and nothing about its buildings. `site_models.js` keeps its `plaza`
and `ring` radii private inside `settlement()`. So `PLAZA` in
`npcs_runtime.js` is a **copy** of those numbers, read off that function on the
day this was written (town plaza 12, hamlet plaza 8), and the people stand on a
smaller ring inside it: 8 m in a town, 5 m in a hamlet, 1.6 m at a ruin, which
is inside the pillars that start at 3 m. Stations stand further out again at
10.5 m and 6.8 m. `auditNpcSpots()` holds the ring inside the flattened ground
and clear of the well, and the test measures the closest pair of people in a
town of nine at 5.47 m. **If `site_models.js` ever shrinks its plaza, the people
will stand in a wall and nothing here will notice.** The fix is for
`site_models.js` to export its layout radii; until then this note is the record.

**A key collision main.js has to settle: M.** `main.js` line 216 binds `m` to
`audio.toggleMusic()`, and `06` gives `m` to the Map. Registered as written, one
press does both: the map opens and the music stops. The panel keys W5 claims are
`v` (Crafting), `m` (Map) and `escape` (Settings); Talk and Trade have no key and
are opened by code. `v` and `escape` are free. `m` is not. The Settings panel now
owns music and sound as proper toggles with volume sliders, so the cleanest fix
is to drop lines 216 and 217 from `main.js` and let Escape own sound; if the
quick toggles are wanted, move them to another pair of keys. This is Fable's call
and no code here assumes either answer.

**`inventory.sell(where, opts)` has an `onSell` hook** that asks somebody for a
price. The Talk engine does its own vendor arithmetic and does not use it, so
gold is never counted twice. If the Bag window's right click sell should go
through whoever is standing in front of you, wire
`createInventory({ onSell: ... })` to the open Talk engine; the pricing pieces
(`basePriceOf`, `quoteSell`, `memoryOf`, `noteTrade`) are all exported.

## 8. Verification

`npm test` is green. What was measured, rather than asserted:

- **The map.** 128 x 128 samples at 62.5 m over 8 km. The real draw, through a
  recording context so every field sample, road lookup and site lookup is done
  for real: 59 ms cold, 36 to 39 ms warm, against a 100 ms budget the test
  fails on. 160 x 160 was tried first and measured 75.7 ms cold, which is inside
  the budget here and too close to it elsewhere, so the count came down a step.
- **The vendor rules**, both directions, with the arithmetic printed: the sell
  rate from 30% down to the 5% floor unit by unit, the buy price up by 1.05 a
  unit, and the hour of memory expiring and not expiring either side of the
  boundary.
- **Training**, refused four ways (wrong teacher, already past 40, not enough
  gold, nothing left to buy) and allowed two ways (to 40, and as far as the
  purse goes), with the skill and the gold read back after.
- **The trade rules**: one tick moves nothing, two ticks move everything, and
  each of four kinds of change unticks both, including a change made by the
  other side.
- **Crafting refusals**, all five kinds, and both the pack-full paths: the one
  the panel greys before you press, and the one where the pack fills between the
  check and the swing, where the materials are handed back and the line says so.
- **Both the fake inventory and the real one.** Each of the Talk and Crafting
  suites ends with a section driving W3's `createInventory` rather than a stand
  in, so the adapters are proved against the file they adapt.

Not verified, because there is no browser here: anything on screen. Nobody has
seen a name plate project, a panel lay out, the map canvas paint, or a slider
move. Fable verifies those.
