## 1. The create calls, in the order they go in at boot

`createForageField` needs a world field and a way to ask for trees. It does NOT
import flora, tree_gen or arbor: the trees arrive as plain records, so whoever
owns the forest can change its own shape without breaking foraging.

```js
import { createForageField, seasonAt, SEASONS, SEASON_MS } from '../world/forage.js';
import { createForaging } from './foraging.js';

// AFTER runtime (which owns field and flora), and after the scene
const forage = createForageField(sc, {
  field: runtime.field,
  treesFor: treesForChunk,          // section 2. Without it, nothing grows on a trunk.
  season: seasonAt(Date.now()),
  seed: runtime.field.seed,         // optional; defaults to field.seed
  // abundance: 1, scale: 1.4        the reference's two sliders
});

// AFTER inventory, progression, hud, audio, floaters, actor and combat exist
const foraging = createForaging({
  field: forage,
  inventory, progression, hud, audio, floaters,
  character: state.character,
  actor,
  combat,          // NOT optional in practice: see section 6
});
ctx.foraging = foraging;
ctx.useItem = (item, where) => foraging.useItem(item, where);   // section 5
window.__bw.forage = forage;
window.__bw.foraging = foraging;
```

Per frame, near the other world updates and before `hud.update`:

```js
forage.update(player.pos.x, player.pos.z, seasonAt(now));
```

`update` is cheap when nothing moved: two integer compares plus a regrowth
sweep. It reloads the 3x3 ring only when the player crosses a chunk edge, and
rebuilds the whole ring only when the season turns.

## 2. How flora hands over trees

`treesFor(cx, cz)` returns `[{ x, z, radius }]` for the 64 m chunk at those
chunk coordinates, in world space. `radius` is the trunk radius at the base, in
metres. Anything else on the record is ignored.

Chunk edges: the reference only ever attaches a trunk dweller to a tree in the
chunk it is building, so a chunk-local list is correct. Handing back a slightly
wider list is harmless; the records will simply sit a little outside the chunk,
exactly as the reference's own do.

**From the current `flora.js`** (records are `{ x, z, gy, s, ry, vi, chunk }`,
and the base radius lives on the baked variant, which is what `createStumps`
already reads):

```js
function treesForChunk(cx, cz) {
  const key = `${cx},${cz}`;
  const out = [];
  for (const f of Object.values(runtime.flora.kinds)) {
    if ((f.kind || 'tree') !== 'tree' || !f.variants) continue;
    const n = f.variants.length;
    for (const t of f.trees) {
      if (t.chunk !== key || t.felledUntil) continue;
      const v = f.variants[variantOf(t, n)];
      out.push({ x: t.x, z: t.z, radius: (v?.baseR ?? 0.35) * t.s });
    }
  }
  return out;
}
```

**From `arbor.js`'s `placeTrees`** (V6's spots are `{ x, z, scale, yScale, yaw,
protoIndex }` and the prototype carries `radius`):

```js
const treesForChunk = (cx, cz) => arbor
  .placeTrees(biomeAt(cx, cz), cx, cz, 64, field.seed, { heightAt })
  .map((s) => ({ x: s.x, z: s.z, radius: stand[s.protoIndex].radius * s.scale }));
```

**With no `treesFor` at all** the field still runs and still grows everything
that sits on the ground, and `forage.stats.treeless` counts the chunks it
happened in. That number being equal to `forage.chunkCount` is the signature of
the wire being missing, rather than of a wood with no trees in it.

A felled tree does not take its mushrooms with it. Chopping does not rebuild the
forage layer, so a chanterelle keeps standing where the oak used to be until its
chunk is unloaded. Fixing that means calling `forage.update(x, z, season)` after
a fell with the chunk dropped first, and it is not wired: see section 8.

## 3. Click routing for main.js

A forage record under the cursor and within `HARVEST_REACH` (2.5 m) takes the
click **before** `interact.click()`. It goes after the loot sack, the NPC and
the station (each of those is a deliberate thing a player walked up to) and
before monsters, skinning and interact, because a mushroom at your feet is
nearer the cursor than the oak behind it and `interact.js` does not know it is
there at all.

In `onClick`, one line, straight after the station block:

```js
      // a mushroom at your feet beats the oak behind it
      const pick = forage.pick(ray);
      if (pick) {
        const r = foraging.harvest(pick.rec, now);
        if (r.ok || r.reason !== 'too_far') return r;   // too far falls through to the tree
      }
```

The `too_far` fall-through is the one judgement here: pointing at a patch across
a clearing and clicking should still swing the axe at what is actually in reach,
rather than printing "stand over it" and doing nothing.

The hover hint, in the frame loop **after** `interact.update(dt, now)`:

```js
      const hov = forage.pick(aim());
      if (hov) hud.setHint(foraging.hoverText(hov.rec));
```

Wrinkle, stated rather than hidden: `interact.js` memoises the last hint it set
and only writes when its own text changes, so after the forage line has
overwritten the hint, moving the cursor back onto the same tree will not restore
interact's line until the tree changes. The one-line fix is on interact's side
(drop the memo, or expose `hint(text)`), which this agent does not own. Until
then it costs a stale hint on one hover, never a wrong click: the click is
computed fresh every time.

`E` is not wired to foraging. Picking is a click.

## 4. The season readout

```js
import { seasonAt, seasonProgress, nextSeasonAt, SEASONS, SEASON_MS } from '../world/forage.js';

seasonAt(Date.now())        // 'Spring' | 'Summer' | 'Autumn' | 'Winter'
seasonProgress(Date.now())  // 0 to 1 through the current season, for a dial
nextSeasonAt(Date.now())    // the millisecond it turns
forage.season               // what the loaded ring was actually built for
forage.setSeason('Autumn')  // the dev bench; rebuilds the ring
forage.tally()              // { chanterelle: 356, nettle: 366, ... } standing right now
```

A season is **three real days** (`SEASON_MS` 259,200,000 ms), the homestead
game's rule. A year is four of them, twelve real days. The epoch is the unix
epoch, so day 0 is Spring; pass a second argument to `seasonAt` to shift it.

`forage.update(x, z, season)` is the only thing that changes the season, so the
HUD and the world can never disagree about what season it is: read
`forage.season` for the readout, and hand `seasonAt(now)` to `update`.

## 5. The `useItem` hook for `win_bag`

`win_bag.js` already calls `ctx.useItem(item, { pack: i })` from the bag's "use"
menu entry, for any base that is a material or stacks, and says
"nothing has been written yet that uses ..." when `ctx.useItem` is missing. One
line in main.js closes it:

```js
ctx.useItem = (item, where) => foraging.useItem(item, where);
```

`useItem(item, second, opts)`. The second argument is either a pack address
(`{ pack: 3 }`, which is what the bag hands over) or an actor to apply it to
(anything carrying `maxHealth`, `buffs` or `pos`). With an address, exactly one
of the stack is spent; without one, nothing is spent and the effect still
happens, which is what the dev bench wants.

It returns `{ ok, reason, text, healed?, poison?, buff?, restored?, spent }` and
`text` is what went to the HUD. `ok` is false, with a reason in words, for:

| reason | when |
| --- | --- |
| `no_use` | the base has no `use` block. A longsword. |
| `nothing` | a `caution` forageable eaten raw. Nothing spent, and it says why. |
| `nothing_to_cure` | an antidote with no poison in you. The bottle stays corked. |
| `no_actor` | nobody to apply it to |
| `unknown` | not an item |

## 7. What was measured

Every number below came out of `node src/world/forage.test.mjs` and
`node src/game/foraging.test.mjs`, not out of an estimate.

### The season clock

| claim | measurement |
| --- | --- |
| a season is three real days | `SEASON_MS` 259,200,000 ms; day 0 Spring, day 2.9 Spring, day 3 Summer, day 6 Autumn, day 9 Winter, day 12 Spring |
| it wraps backwards | `seasonAt(-1)` is Winter |
| a year visits four seasons and no fifth | 48 samples over twelve days give exactly the four names |
| regrowth is three game days | 1,080,000 ms, eighteen real minutes |

### The table

22 entries: 19 edible, 1 toxic (fly agaric), 2 caution (elderberry, nettle).
Entries per biome: meadow 18, boreal 13, sakura 18, mountain 10, snow 13,
beach 5, desert 2.

**Winter is bare.** Not one of the 22 lists Winter, so every biome grows zero

Beach grows: wild honey, blackberry, rosehip, nettle, dandelion. Desert grows:
wild honey and wild figs. Both lists are additions and each is justified in a
comment at the entry (a beach rose holds a dune; bees nest in a desert snag; a
fig at an oasis is the one fruit a desert honestly grows). Nothing in the table
is a cactus fruit, so nothing pretends to be one.

## 8. What was invented, and why

Each of these is a rule the work needed and could not find in a document.

### Winter, and the bare wood

The reference has three seasons; this game's clock has four. Rather than invent
a fourth season's worth of plants, the table is ported honestly and Winter is
empty. **The consequence is that foraging stops dead for three real days out of
twelve.** That is a design decision worth a second opinion, not a bug, and the
one-line fix if it reads badly is to add `'Winter'` to rosehip and lingonberry,
both of which really do hang on under snow. `auditForage().winter` counts them,
so the change is visible from the audit.

### The biome port

`BIOME_FROM` maps the reference's five forest types onto this game's eight
biomes: Temperate broadleaf to meadow, Boreal conifer to boreal and to snow at
half, Birch grove to sakura, Mediterranean pine to mountain, Tropical wet to the
wettest meadow band (`moist >= 0.62`, which is the line `field.js` uses for
sakura). Desert and beach are in no reference forest and are listed by hand.

### The clearing rule

The reference tests a clearing against the same fbm its own tree layout uses.
This module is not given that noise and IS given the trees, so a clearing here is
a spot no crown reaches: `radius + 2.5 m` clear of every trunk. That is closer to
what the word means and it cannot disagree with the forest that is actually
drawn.

### The berry budget

The reference builds every berry from an 8x6 sphere (80 triangles). Elderberry's
seven umbels of fourteen came to 7,840 triangles for one prototype, and
blackberry to 2,104. Small round things are built from a 6x4 sphere (36
triangles) here, and elder carries four umbels of nine. Nothing else was changed
and every silhouette is the reference's.

### `honey` and `nut`

The brief asked for a base per forageable "plus `honey`, `nut`". Adding two bases
nothing grows is exactly the "nine unlock ids that matched no catalog entry" bug,
so instead the reference's Wild honey **is** `honey` and its "Acorns &
chestnuts" **is** `nut`, named Chestnuts. Both words a recipe wants exist, both
are things you can pick up, and there are no orphans in either direction.

### `difficulty` per forageable

The reference has no skills. Each entry carries a Foraging difficulty set from
how hard it is to find and to know, roughly the inverse of its `per`: dandelion
3, nettle 5, blueberry 8, chanterelle 18, porcini 25, wild ginger 28, cacao 30,
morel 35, wild honey 40.

### The yield ladder

Nothing states what a patch gives. One at 0 to 39 Foraging, two at 40 to 79,
three at 80 and over. Deterministic rather than rolled, so a player can feel the
skill move.

### `forageMeal` and `foragePotion`, not `meal` and `potion`

`recipes.test.mjs` (another agent's file, not edited) states out loud that there
are exactly six meals and eight potions, and those two sentences are true of the
authored six and eight. The fifteen forest dishes and seven forest draughts are
their own two families so both counts stay honest, and a crafting window can
show them as their own list.

### The poison is a poison

`03-ITEMS-LOOT.md` has no blade coating and nothing in this game applies one, so
Woodland poison does what a poison does to whoever opens it. The recipe is
Poisoning at the alchemy table, which is where the skill's "applies poison to
blades and food" lives; the day a blade coating is written, the item gets a
`coat` field and `useItem` gets one more branch.

### The `use` block

`items.js` had no notion of an item that does something when you use it.
`use` is one field with one consumer (`foraging.useItem`) and six shapes: `heal`,
`poison`, `cure`, `restore`, `buff`, `nothing`. `auditForageBases()` fails if a
forage base has none, if a toxic one does not poison, if an edible one does not
heal, or if a buff has no effect block.

## 9. Not verified

* **Nothing here has been run in a browser.** No player has seen a mushroom.
  The geometry is built and its triangles counted in node, the instancing and
  the raycast back-index are exercised against a real `THREE.Scene` and a real
  `THREE.Raycaster`, and the material is constructed, but nothing has been
  rendered. Fable verifies.
* **Nothing in `main.js` calls any of this yet.** Section 1, 3 and 5 are the
  wiring, and until they go in, `forage.pick` is never asked, `ctx.useItem` is
  still missing, and the bag still prints "nothing has been written yet that
  uses chanterelle".
* **`treesFor` has no caller.** The adapters in section 2 are written against
  the current `flora.js` and V6's `arbor.js` and are not executed by any test:
  the tests pass their own `[{ x, z, radius }]` lists. If V2's rewrite of
  `flora.js` changes `variants[i].baseR`, the first adapter needs one line
  changed and `stats.treeless` will say so.
* **A felled tree keeps its mushrooms** until its chunk unloads. See section 2.
* **107 draw calls for nine meadow chunks** is real and measured, and it is a
  lot. The reference does the same thing and runs at 60 fps on a laptop, but it
  has not been profiled in this game with everything else on screen. The lever is
  `abundance` on `createForageField`, which scales every count linearly.
* **`bonuses.nightSight`**, which the nightsight draught sets, is on W1's list of
  bonus keys that nothing reads yet. The buff is real, the recompute is real, and
  until `player.js` or the lighting reads that key the player will not see the
  dark thin out. Every other buff this file grants lands on a field the game
  already consumes: `healthRegen`, `staminaRegen`, `manaRegen`, `resists.cold`,
  `resists.poison`, `bonuses.carry`, and the five stats.
* **No forage sound of its own.** `pickup`, `denied`, `heal`, `buff` and
  `spell_poison` are borrowed from the existing cue table. Nothing in
  `audio.js` is an eating or a drinking sound, and nothing in
  `docs/sfx-wishlist.txt` asks for one. Worth one.
* **The hint memo wrinkle** in section 3 has not been observed, only reasoned
  from `interact.js`'s `lastHint`.
