# G3: underground, ranged and casting, bosses, flying, weaknesses

W2 shipped the monsters runtime and ended with a list of four things it had
deliberately not done. This is that list, built, plus the one loose thread
`actor.js` left hanging in its own header.

| file | what changed |
| --- | --- |
| `src/game/monster_ai.js` | new. The pure half: placement in a level, the standoff, the cone, the spells, the boss plans, the hover, the weakness multiplier |
| `src/game/monsters.js` | the runtime half: the dungeon layer, projectiles, casts with an interrupt, phases with a name plate, flight, `swingAt` |
| `src/game/monsters.test.mjs` | 113 checks became 275 |

Nothing else was touched. `combat.js`, `world_runtime.js`, `dungeon.js`,
`monster_models.js`, `main.js` and every file under `src/mmo/` are exactly as
their owners left them.

---

## 1. What `world_runtime.js` has to expose

**One new export, and it is the only blocker.** Everything else G3 needs is
already there (`inDungeon`, `dungeonLevel`, `dungeonSite`, `clampWalkable`,
`heightAt`).

```js
/** The level you are standing in, as rooms on the 2 m grid, or null above ground. */
dungeonLayout() {
  if (!dungeon) return null;
  const L = dungeon.layout;                       // generateDungeon's own object
  return {
    rooms: L.rooms,           // [{ x, z, w, h, cx, cz }] in GRID CELLS
    w: L.w, h: L.h,           // the grid, in cells
    cellSize: L.cellSize,     // 2
    level: L.level, top: L.top,
    kind: L.kind,             // 'dungeon' | 'cave'
    id: dungeon.site.id,
    entrance: L.entrance,     // { gx, gz }
    bottom: L.level >= maxLevel(L.kind),
  };
}
```

`dungeon.layout` is already held in `world_runtime.js` and
`createDungeonScene` already returns it on `built.layout`, so this is a getter
over state that exists. **`dungeon.js` needs no new export at all.**

The shape above is the raw `generateDungeon` layout with two extra fields
(`id`, `bottom`), and `normalizeDungeonLayout` in `monster_ai.js` accepts
either that or the tidier `{ rooms: [{ x, z, w, h, kind }], gridW, gridH,
level, bottom, cellSize, siteId }` the brief named. Room `kind` is optional: a
room labelled `entry`/`entrance` or `boss`/`deep` wins, and with no labels the
entry room is the one holding `entrance` (falling back to room 0, which is
where `dungeon_gen.js` puts it by construction) and the deepest is the room
whose centre is furthest from it, which is the same rule `dungeon_gen.js` uses
to place the stair down.

**Without it nothing is guessed at.** `normalizeDungeonLayout` returns null
when it cannot get a grid width, the dungeon layer stays empty, and
`monsters.js` logs one warning naming this file. A level whose rooms cannot be
turned into metres would put monsters at the wrong coordinates and then have
`clampWalkable` drag them onto the nearest floor, which is a broken feature
wearing the face of a working one. Measured: with today's `world_runtime.js`,
ten frames underground give `monsters.count === 0`, no overworld leak, and
exactly one warning.

## 2. What `main.js` has to call

### The one swap: `monsters.swingAt`

```js
// src/game/main.js, onClick(), where it now reads combat.queueSwing:
const r = monsters.swingAt(actor, mon.actor, { now, jumpAttack: player.airborne, ...extra });
```

Same arguments, same return, same resolver. `swingAt` reads
`defender.vulnerability` (which `actor.js` builds from `fireWeak`,
`energyWeak`, `holyWeak` and `silverWeak`, and which nothing in the tree was
reading) and folds it into `opts.multiplier`. `combat.landSwing` already puts
`opts.multiplier` back through `combat_rules.damage` with the same roll and the
same crit, which is **the real resolver and not a second formula**. See section
5 for why that is the path and a negative resist is not.

`abilities_runtime.js` should do the same wherever it calls
`combat.queueSwing(actor, monster, ...)`: pass
`multiplier: (existing || 1) * monsters.weaknessMultiplier(actor, monster, { damageType })`.
That file is G2's; this is the note, not the edit.

### Nothing else changes

`monsters.update(dt, now, playerActor, night)` is still the same call in the
same place in the frame, still before `combat.update`. It now notices for
itself which layer it is on:

```
runtime.inDungeon false  ->  the streamed near ring, as before
runtime.inDungeon true   ->  one level, held whole, from dungeonLayout()
```

A change of level or of site empties one layer and builds the other. `rescan`
does the same, so the existing call after a teleport or a respawn is correct
underground too.

### Worth having on `window.__bw`

`monsters.projectiles()`, `monsters.warnings()`, `monsters.levelSpawns()`,
`monsters.layer`, and the grown `monsters.stats`
(`shots, casts, interrupted, slams, summoned, phases` on top of W2's six).

### One thing that is not wired and could be

The boss name plate is a canvas sprite built in `monsters.js` and needs
`document`. In node it is skipped and everything else still runs. If the HUD
would rather own it, `plateText(row, health, maxHealth)` is pure and returns
`{ name, phase }`.

## 3. Underground

### The roll

Habitat by depth: `dungeon1`, `dungeon2`, `dungeon3` by level, `cave` for a
cave, straight off `HABITAT` in `src/mmo/monsters.js`.

Per room, keyed `siteId:level:rN`, seeded from that key and the world seed:

- **the entry room holds nothing.** Measured: a three room level puts groups in
  rooms 1 and 2 and none in room 0.
- **every other room holds one group**, plus one more for each
  `ROOM_AREA_PER_EXTRA_GROUP` = 160 m² of floor, capped at 3.
- **the deepest room holds the boss and nothing else, and only when `bottom`.**
  Measured: at level 3 bottom, exactly one boss, in room 2, and the boss room
  holds one body; at level 3 not-bottom, zero bosses anywhere and room 2 holds
  an ordinary group instead. No ordinary room ever rolls a boss: the minion
  roll re-rolls past one.
- A cave has no boss because no boss lives in the `cave` habitat, and it says
  so rather than inventing one.

**The density interpretation.** 05-WORLD-CONTENT gives underground density as
"about one monster group per 40 m of dungeon corridor" and never mentions a
room. Read here as one group per room plus a second for a room big enough to
be two. `dungeon_gen.js` builds rooms of 3 to 8 cells a side at 2 m a cell, so
36 to 256 m², and 160 m² makes about the largest sixth hold two. **This is the
one constant to change if it plays thin.** Measured on a six room level: 15
bodies.

### The keys, and staying cleared

`deep:1:r4:g0:goblinWarrior:0` carries the site, the level, the room, the group
and the index. That is what goes into `character.deadUntil`, so a room cleared
before you took the stair is still clear when you climb back up. Measured:
kill one, leave the level, come back, and that key alone is missing while the
rest of its room is standing.

Leaving despawns everything. Coming back re-rolls from the same seed and gives
a byte-identical roster (`JSON.stringify` equal), minus the dead list. Level 2
of the same shaft is a different roll from level 1, and another shaft is
different again.

### Pathing

Every step goes through `runtime.clampWalkable`, not just placement:
`stepToward` and `stepAway` take a `clampXZ` and `stepMonster` passes it
whenever `runtime.inDungeon`. Measured against the **real** `generateDungeon`
level and the **real** `clampToWalkable`: 17 bodies, ten seconds of chasing a
player walking a circle, **0 of 10,200 monster frames inside the rock**.

Cap: `DUNGEON_CAP` = 24 bodies at once, ranked by distance to the player, the
same rule the surface uses.

## 4. Ranged, casting and breath

### Which rows, and how it is decided

`RANGED_TAGS` in `monster_ai.js` maps note tags to modes, and
`auditRangedRows()` throws at load if a row's notes and its mode disagree in
either direction. Eight rows in the whole roster attack at range:

| mode | tag | rows |
| --- | --- | --- |
| thrown | `throwsKnives`, `rangedSpikes`, `boulder` | Goblin Scout, Manticore, Cyclops |
| cast | `casts` | Cultist, Lich, the Ashen King |
| breath | `breath` | Wyvern, Bone Dragon |

**There is no `bow` and no `crossbow` tag in `NOTE_TAGS` and no row carries
one.** Both are in the table anyway so the day a row gains one it shoots
instead of silently walking into melee. `frostNova` is deliberately not ranged:
it goes off around the frost giant, not across a room.

### The standoff

`RANGED_NEAR` 8 m, `RANGED_FAR` 14 m. Beyond 14 it closes; under 8 it walks
**backwards, still facing you**, until it is back at 8; between the two it
stands and throws. The back-off trigger is the near edge of the band and not a
smaller number, because a smaller one leaves a dead zone where a monster stands
closer than it ever meant to and never corrects.

Measured, 300 frames with the player standing still at 11 m: gap held at
**11.00 m to 11.00 m**, closest approach 11.00 m, wanted to throw on 300 of 300
frames. Then the player walks in to 3 m: it backs out to **8.10 m** over 51
moving frames and is still facing him to within 1e-6 radians. A wolf, in the
same harness, still walks all the way in to 2.37 m.

**Cornered.** If backing away moves it less than `CORNER_MOVE_FRACTION` (25%)
of the step it wanted for `CORNER_SECONDS` (0.6 s), it stops trying and fights
with its hands. Measured against a wall at x = 9: cornered at frame 45, never
past the wall, and back to standing off once the room opened up again.

### The projectile

Thrown and shot go out through **`combat.queueSwing`**, the same call the
player's click makes. Two things had to be true for that to work:

1. **The weapon's `reach` is raised to its range.** `combat.landSwing` throws
   away any blow whose distance has grown past `reachBetween * REACH_SLACK`,
   which for a natural reach of 1.5 m is 2.9 m. A knife thrown twelve metres
   would have been queued and then binned three hundred milliseconds later,
   with nothing said. `rangedWeaponFor` copies the row's own natural weapon and
   changes exactly two fields, `ranged` and `reach`; the skill id, the damage
   range and the swing speed are untouched, so `attackSkill`, `defenceSkill`
   and `swingSeconds` still return the row's tabled numbers.
2. **The flight time is `combat.SWING_LAND_S`**, imported rather than
   re-guessed, so the mesh and the number arrive together.

Measured: the goblin scout threw on frame 140 (its tabled 2.4 s rhythm, held by
`queueSwing`'s own cooldown), the knife was never at the target before its time
on any frame, and it arrived on **frame 18, which is 0.3 s at 60 Hz**, and the
player was 5 health down with the goblin the only thing alive in the level.

**A miss flies past.** Whether a swing hit is not known when it is thrown: the
roll happens inside `combat.update`, one call later. So the shot notes the
defender's health as it leaves and, on the frame after it lands, asks whether
that number moved. It did not, so it carries on `PROJECTILE_OVERSHOOT_M` = 4 m
past the ear instead of stopping in the chest.

### The cast

Through **`combat.queueSpell`**, with a spell drawn from the row and no second
damage table: the base is the row's own tabled damage range, so a cultist's
fireball is its 8 to 14 and a lich's bolt is its 30 to 50.

| row | spell | type |
| --- | --- | --- |
| `casts`, kind undead | a bolt | energy |
| `casts`, anything else | a fireball | fire |
| `poisonBreath` | a breath, 6 m cone | poison |
| `breath` | a breath, 6 m cone | fire |

Cast time `CAST_SECONDS` 1.5 s, breath 1.0 s, held with the model in its cast
pose. **The rhythm is the row's own tabled swing speed**, not a new number:
`lastSwingAt` is stamped when the cast starts and the next one waits out
`swingSeconds`. Measured: two consecutive cultist casts **2.60 s apart against
a tabled 2.60 s**.

**Interrupt.** 04-CLASSES-ABILITIES: "interrupted only by taking damage over
10% of your health". Same rule, no softer version. Measured on a cultist of 80
health: a blow of **7 does not break it**, a blow of **9 does**, the counter
goes to 1, and the line "loses the words" is in the log.

**The cone.** `coneTargets` is pure and measured both ways: of five candidates
around a breathing wyvern, the one in front is caught and the one behind, the
one at 9 m, the one out to the side of the 60 degree cone and the corpse are
not. One of five.

## 5. Bosses

`BOSS_PHASES` gives 66% and 33% and nothing else. The behaviours are
08-POLISH-CONTRACT's list, **one to each boss so all four are reachable in
play** rather than three of them being written and never seen. This assignment
is authored:

| boss | 66% | 33% |
| --- | --- | --- |
| the Ashen King | summon | enrage |
| the Mother of Spiders | summon | enrage |
| the Warden of the Cut | slam | enrage |
| the Drowned Knight | slam | retreat and heal |

The Drowned Knight carries the coward's phase because every boss row is
`flees: 'never'` and nothing else in the roster would ever run, and a knight
going back to deep water is in character. Argue with it in `BOSS_PLANS`.

Each phase says one line, in the boss's voice, once. Measured: at 50% health
the counter goes to 1 and the line appears exactly once; two more seconds of
frames and it is still 1 and still once.

- **enrage** adds `ENRAGE_SWING` = 0.30 to `bonuses.swingSpeed`, which
  `combat_rules.swingSeconds` already reads. Measured: 4.40 s to 3.08 s,
  exactly `(1 - 0.30)`.
- **summon** puts `SUMMON_COUNT` = 3 of the level's habitat down in a ring of
  `SUMMON_RING_M` = 5 m, clamped to walkable floor. Measured on the Ashen King:
  3 summoned, count 5 to 8, all of them dungeon3 rows and none a boss, all
  within 8 m. They are `ephemeral`: killing one writes **0 entries** into
  `character.deadUntil`, because they were never a slot in the level's roll and
  an entry for them would sit in the save matching nothing. Killing the boss
  itself does write its key.
- **slam** puts a ring `SLAM_RADIUS` = 6 m on the floor for `SLAM_WARN_S` = 1 s
  and then hits everything still in it, and again every `SLAM_EVERY_S` = 9 s.
  Measured, same fight run twice: standing in the ring costs **128**, stepping
  out of it costs **0**.
- **retreat** flees and heals `RETREAT_HEAL_PS` = 40 a second for
  `RETREAT_SECONDS` = 8, through `combat.heal`.

**Why the slam goes through `queueSpell` and not `queueSwing`.**
`combat.landSwing` bins a blow past `reachBetween * REACH_SLACK`, which for a
boss is under 5 m, so a 6 m slam queued as a swing would be silently thrown
away for every target but the one under its feet. `queueSpell` has no reach
gate and takes an exact `travel`. The cost, said out loud: `resolveSpell` has
no armour term, so a slam is not reduced by AR. The ground going out from under
you is not a thing a breastplate stops, and this is the trade, not an oversight.

**Boss loot** needs no new call. `loot_drops.rollFor` already reads
`boss: !!m.boss` off the row and hands it to `loot.rollKill`, which applies the
purple floor and the double roll. There is no `loot.bossRoll`; `died()` was
already routing it correctly and still is.

## 6. Flying

Four rows: Cave Bat, Harpy, Wyvern, Bone Dragon.

`HOVER_MIN` 2 m, `HOVER_MAX` 3 m, bobbing on a `HOVER_HZ` 0.45 sine, climbing
at `HOVER_CLIMB` 3.5 m/s. Measured over 200 frames of an idling cave bat:
**2.000 m to 3.000 m** over the ground, 1.000 m of bob, never outside the band,
and it drifted 9.30 m while doing it.

The height is kept on `ai.alt` and not read back off `pos.y`, because every
movement branch writes `pos.y` from `heightAt`: a height derived from it is
knocked back to the floor on every frame the thing moves, and the bat spends
its life climbing the same six centimetres. That was a real bug in the first
draft and the test caught it at 0.058 m.

**The swoop, and "hit normally".** `combat.actorDistance` is three dimensional,
so a harpy three metres up genuinely cannot be reached by a man on the ground.
That is not special-cased: instead, a flyer entering its attack state dives to
the floor and holds low for `SWOOP_SECONDS` = 1.2 s, which is the window to hit
it back. Measured: attacking, the altitude goes to **0.000 m**; with the target
gone it climbs back to 2.976 m and never drops below 2.000 m again over the
next 300 frames.

## 7. Weaknesses

`actor.js`'s own header, note 6: "`resistOf()` clamps a resist at zero, so
`fireWeak` cannot be carried as a negative resist. It is carried as
`actor.weakTo` and `actor.vulnerability`, and W2 applies it as a damage
multiplier." Until now nothing did.

**The path taken, and why.** `combat.queueSwing`'s `opts.multiplier` is put
back through `combat_rules.damage` by `landSwing`, with the same roll and the
same crit as the original swing. That is the real resolver: no arithmetic
happens in `monsters.js` beyond multiplying two multipliers together. The two
paths considered and rejected:

- a negative typed resist: `resistOf` clamps at 0, so it cannot be expressed;
- scaling the applied damage after the fact in the caller: that is a second
  damage formula, and the floating number would have to be rewritten to match.

The kinds a blow can carry: the weapon's `damageType` (or an override, for an
enchant), the weapon's **material** (`silver` is a material in `ores.js`, not a
damage type), and `holy` (which `abilities.js` writes as a damage type on
Consecrate Weapon). Only the largest single vulnerability applies; two do not
stack, because nothing in the documents says they should.

Measured, pure: an iron golem carries `{ energy: 0.25 }`, an energy blow gives
**1.25** and a steel one gives **1.0**; a wolf gives 1.0 for everything; a
skeleton gives 1.25 to holy; a werewolf gives 1.25 to a silver-material weapon
and 1.0 to an iron one.

Measured through the real resolver, the same swing with the same seeded rng
twice: `combat.queueSwing` took **133**, `monsters.swingAt` took **167**, a
ratio of **1.2556** (the gap from 1.2500 is `Math.round` on 133.6, not a second
formula).

## 9. What is still not done

- **`world_runtime.dungeonLayout()` does not exist yet.** Until it does the
  dungeon layer is off, loudly. Section 1 is the whole of the ask.
- **The name plate needs a browser.** Headless it is skipped.
- **Group buffs.** The Orc's `warCry` still buffs nobody. It is not a ranged
  attack, a phase or a flight, so it was out of this brief; it wants the same
  treatment `alertGroup` already has.
- **`frostNova`, `webRoot2`, `paralyse15`, `knockback`, `charges`, `regrows`,
  `threeHeads`, `healsInDaylight`, `manaDrain`, `phylactery`** are still note
  tags nobody reads. `auditRangedRows()` covers only the ranged ones and the
  boss plans; the rest are a separate job and are named here rather than left
  to be discovered.
- **A boss's minions do not despawn when it dies.** They are `ephemeral` so
  they leave no trace in the save, but they stay standing until the layer
  changes. Arguably correct; unarguably undecided.
