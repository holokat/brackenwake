The user's words, 2026-09-05:

> the old farmstead hardcoded mechanics. we need to fix that, and lets redo the
> models for them, current animal models look really bad, including birds.

Both halves are done. This page is what is left for other hands: the lines in
`src/game/monsters.js` and `src/mmo/monsters.js` that F1 was not allowed to
write, each quoted where it goes, with what it buys and what it costs.

Everything below was measured, not assumed. Where a claim is unverified it says
so in those words.

**The bug the user found, in one line.** `monsters.spawn()` reads
`buildMonsterModel(rec.id)` and returns `null` when there is no body. Every tier
0 row returned `null`, so the monster layer refused to stand a rabbit up at all,
and the only animals in the world were the decorative ones `fauna.js` drew,
which nothing could target. There is now a body for every tier 0 row, so that
call succeeds and a rabbit is an actor.

## 2. THE ONE LINE. `monsters.chunkFor` has to ask for the critters

`src/game/monsters.js`, in `chunkFor`, currently:

```js
  function chunkFor(cx, cz, night) {
    const k = `${cx},${cz}`;
    const had = chunks.get(k);
    if (had && had.night === night) return had;
    const entry = {
      cx, cz, night,
      recs: field ? spawnsForChunk(field, cx, cz, { night, sitesNear, spawnPoint, spawnKeep, chance: opts.groupChance }) : [],
    };
    chunks.set(k, entry);
    return entry;
  }
```

Add one line after `const entry = { ... };`:

```js
    // The world's own animals. src/world/fauna.js decides where a rabbit
    // belongs (biome, forest edge, off the water, out of the towns); this layer
    // stands it up. The records are this file's own record shape, so the cap
    // ranks them, `deadUntil` remembers them and the sweep despawns them
    // exactly as it does a wolf. See docs/mmo/wiring/F1.md.
    if (typeof runtime?.critterSpawns === 'function') entry.recs = entry.recs.concat(runtime.critterSpawns(cx, cz, night));
```

`runtime` is already in scope: `createMonsters(sc, runtime, opts)` holds it, and
`world_runtime.js` already exports `critterSpawns` (it returns `[]` underground,
because a level is not a meadow).

**Why not `HABITAT`.** Critters are deliberately NOT added to the `HABITAT`
tables in `src/mmo/monsters.js`, and this is the one place F1 argues with its
own brief. `spawnRollFor` picks ONE id from a place's list and rolls one group;
adding rabbits to `meadow.day` would mean a chunk holds rabbits OR bandits, at
the bandits' density, with no way to say "deer keep the forest edge" or "gulls
keep the coast, not the open sea". Those rules are the whole value of the fauna
layer and there is nowhere in `HABITAT` to put them. The concatenation above
keeps two independent densities and one shared cap, which is what is wanted.

**Verified:** `fauna.test.mjs` merges the two lists over eighty real chunks and
checks that no key collides, that every merged record ranks under the cap's own
sort, and that `monsters.blockedAt` agrees that every critter may stand where
fauna put it. **Not verified:** the line above, because it is not written yet.

## 3. Three rows need the `flying` tag

`src/mmo/monsters.js`. `isFlyer(row)` is `notes.includes('flying') || kind === 'flying'`,
and `monsters.js` passes that as `ctx.flying` into `stepMonster`, which is the
whole of what makes a thing leave the ground. Today the hawk carries the tag and
the gull, the crow and the goose do not, so three of the four birds walk.

```js
critter('gull', 'Gull', 3, 9.0, [2, 6], { notes: ['flying'] });
critter('crow', 'Crow', 3, 9.0, [2, 5], { notes: ['flying'] });
critter('goose', 'Goose', 5, 6.0, [2, 6], { notes: ['group', 'flying'], ... });
```

The hawk already reads `notes: ['flying', 'dives']`. Nothing else in tier 0
should get it: a frog is not a bird.

`'dives'` is in `NOTE_TAGS` and nothing reads it. That is fine as an intent
marker as long as somebody eventually makes a hawk stoop; a note nothing reads
is decoration, and this repo has been bitten by exactly that before.

The whale is `kind: 'beast'`, not `'critter'`, and carries `huge` and
`coastOnly`. Neither is read by `fauna.SPAWN`, which places nothing in open
water and has no row for a whale: M2 owns getting one into the sea.

## 4. Birds fly at 2 to 3 m, and the brief asked for 6 to 12

This is the one place the brief's premise did not survive contact.

The brief said to use the existing flyer path "so nothing new is needed there".
The existing path is `stepMonster`'s `ctx.flying` block, which climbs `ai.alt`
toward `hoverHeight(t, swooping)` from `src/game/monster_ai.js`:

```js
export const HOVER_MIN = 2.0;
export const HOVER_MAX = 3.0;
```

**Measured**, driving the real `stepMonster` with a real gull actor for 600
frames: the altitude climbs off the floor within a quarter of a second and then
stays between 2.00 m and 3.00 m, never outside. That is a bat's height, chosen
so a swordsman can reach a harpy. A gull that circles at three metres reads as a
gull that cannot be bothered.

**Measured, the other half:** a critter's aggro radius is 0, so `ai.target` is
never set, so `ai.state` is never `'attack'`, so `ai.swoopUntil` is never
written, so **a bird on the existing path never lands**. Driven artificially
(`gull.ai.swoopUntil = now + SWOOP_SECONDS * 1000`) it does come all the way
down to the floor and go back up afterwards, so the descent works; nothing calls
for it.

The patch, in `src/game/monsters.js`, replacing the `if (ctx.flying)` block at
the end of `stepMonster`:

```js
  if (ctx.flying) {
    const ground = typeof ctx.heightAt === 'function' ? num(ctx.heightAt(m.pos.x, m.pos.z)) : 0;
    // A BIRD PERCHES. A bat hangs in the air because a bat is a fight; a gull
    // stands on the sand until something walks at it, and takes off when it
    // does. `ctx.perches` is true for a tier 0 flyer and false for everything
    // else, so a harpy is untouched by this.
    const band = ctx.hoverBand || null;
    if (ai.alt == null) ai.alt = ctx.perches ? 0 : hoverHeight(0, false);
    ai.hoverT = num(ai.hoverT) + d;
    if (ai.state === 'attack') ai.swoopUntil = now + SWOOP_SECONDS * 1000;
    const swooping = num(ai.swoopUntil) > now;
    const settled = ctx.perches && !ai.target && ai.state !== 'flee' && ai.state !== 'return';
    let want;
    if (swooping || settled) want = 0;
    else if (band) want = band[0] + (band[1] - band[0]) * (0.5 + 0.5 * Math.sin(num(ai.hoverT) * HOVER_HZ * Math.PI * 2));
    else want = hoverHeight(ai.hoverT, false);
    ai.alt = approachHeight(ai.alt, want, d);
    m.pos.y = ground + ai.alt;
    out.altitude = ai.alt;
  }
```

and where `stepMonster` is called, in `update`:

```js
        mode: mon.mode,
        flying: mon.flyer,
        perches: mon.flyer && mon.row.tier === 0,
        hoverBand: mon.row.tier === 0 ? [6, 12] : null,
        rng,
```

`HOVER_CLIMB` is 3.5 m/s, so a bird takes about two seconds to get from the sand
to six metres and about the same to come back down. That is a take off, not a
teleport, and it does not need a new constant.

**"Takes off when approached" comes free**, and it is worth saying why: a critter
row is `flees: 'always'`, so `fleeCheck` puts it in `'flee'` the instant it is
hurt, and `monsters.js` puts a critter in `'flee'` when the player is inside its
spook range through the same `fleeCheck` path everything else uses. `settled` is
false in `'flee'` and in `'return'`, so the bird is in the air for the whole
flight and the whole walk home, and perches again only once it is idle.

**Unverified:** everything in this section past the measurements. The patch is
written, not run.

## 5. One word, so a flying bird has its wings out

`src/game/monsters.js`, in `update`:

```js
      mon.model.update(d, speed);
```

becomes

```js
      mon.model.update(d, speed, res.altitude);
```

`res.altitude` is already computed and already returned by `stepMonster`; every
other model ignores a third argument. Without it a bird flies with its wings
folded, because a model has no way to know how far off the ground its own group
is. The critter model also exposes `setAltitude(m)` and `setGlide(0..1)` if a
caller would rather push than have it read.

**Measured:** at altitude 0 a gull's wings fold to 0.66 m across and its feet are
on the ground; at 9 m they open to 1.09 m against a tabled 1.10 m span and beat
77 degrees at the shoulder; with `setGlide(1)` the beat stops dead (0.000
degrees over forty frames) and the wings stay out.

## 7. The cap, and what critters cost the roster

`ALIVE_CAP` is 40 bodies over the 7 x 7 near ring, ranked by distance, and
critters now compete for it.

**Measured**, walking a line of 24 positions across the real world field and
asking the real near ring at each step: the ring wants

    14, 18, 15, 25, 17, 5, 5, 0, 0, 0, 5, 10, 12, 11, 9, 8, 5, 0, 3, 4, 2, 3, 1, 0

critters, averaging 7.2 of the 40 body cap.

The number that actually matters is not that one though, it is how many MONSTERS
survive once the two lists are ranked together, so the suite measures that too:
the real night roll of the roster, the real critter roll, sorted by distance the
way `rescan` sorts them, capped at 40 and counted. Nine of the twenty four steps
genuinely want more than the cap, and across those nine the cap keeps

    30+10  30+10  29+11  24+16  26+14  29+11  33+7  32+8  32+8    (monsters + critters)

so at the worst of them the roster still keeps 24 of the 40 slots. The suite
asserts that and the average, so a density raised in `fauna.SPAWN` without
thinking will fail rather than quietly starve the roster.

Per biome, over 20 solid 3 x 3 chunk blocks each (a block is 192 m square), on
the world as it stood while Z2 was still moving it: beach 2.4 animals a block,
sakura 2.1, boreal 1.7, meadow 0.9, desert 0.6, snow 0.3. Over a much wider
sample of single chunks that is 0.24 a chunk in a meadow and 0.03 in the snow.
A solid block of ocean holds none, because a solid block of ocean is not coast
and gulls keep the coast. The suite prints all of it on every run, so the
numbers in this paragraph are a snapshot and the run is the source.

If that stops being enough, the shape of the fix is a share rather than a bigger
number, in `rescan`:

```js
    const keep = [];
    let critters = 0;
    for (const w of wanted) {
      if (keep.length >= cap) break;
      if (w.rec.key.startsWith('critter:') && ++critters > CRITTER_SHARE) continue;
      keep.push(w);
    }
```

Not needed at the measured densities, and it is written here rather than built
so that nobody adds it twice.

## 8. The bodies

Eleven of them, all procedural, all in `dragon_models.js`'s language: generated
fur, feather and keratin as DataTextures with a normal map differenced out of a
height field, lofted tubes rather than stacked boxes, named parts a poser drives.
Every one is measured at import by `auditCritterModels()`.

| field mouse | 510 | 0.04 m | 0.09 m | |

Budget is 900 triangles; the heaviest is the deer at 630. The lengths are
head and body for the four legged ones (a tail is not part of a head-body
length) and beak to tail for the birds, both measured with the parts that would
lie about it detached.

**The whale is M2's row and F1 built it anyway.** `M2` added `critter('whale', ...)`
with a model description and no body. A tier 0 row with no body does not appear
at all, silently, which is the exact failure this whole task was about, so it
got one: one lofted tube, a fluke that beats vertically, two pectorals, a dorsal
and a blowhole. It has no swimming AI and nothing places it; `M2` still owns
that. The `coastOnly` note is not read by `fauna.SPAWN`.

**A new tier 0 row with no body warns at import and fails the suite** rather
than throwing at import. That is a deliberate softening of this repo's usual
"throw at load" rule: the roster is another agent's file, and an animal added
there while its model is being made should break the tests, not the game.

**Colour.** Tier 0 bodies are painted like the animals they are (a fawn deer, a
black crow, a grey and white gull), not by `TIER_COLOUR`. The tier colour rule
exists so a player can read danger at fifty metres; a tier 0 animal carries no
danger to read, and C2's con colours put the tier on the NAME, which is where it
belongs for a rabbit.

## 9. Two changes F1 made outside its own files, and why

Both were forced. Neither adds behaviour.

**`src/game/combat.js`** imported `KINDS` from `fauna.js` and audited its loot
table against it at module load. `KINDS` is gone, so that import was a build
error in every file that reaches combat.js, which is most of them. The import
and the half of `auditLootTable` that read it are removed; the half that checks
the catalog stays. Everything above the "MMO resolver" divider in that file (the
farmstead's `WEAPONS`, `LOOT`, `pickTarget`, `resolveSwing`, `swingText`) is now
**unreachable**: `interact.js` hands it `runtime.fauna`, which no longer has a
`hitTest`, so it refuses with `'no_fauna'` and the click falls through to
`fight.monsters.pick(ray)` in `app/systems/input.js`, which is where a rabbit is
now clicked. **That dead half, and `interact.js`'s two calls into it, should be
deleted by whoever owns those files.** It is left standing because it is not
F1's to delete.

**`src/game/monster_models.js`, `shapeFor`.** M2 landed forty eight new monsters
above tier 0, each naming a `family` that is one of the nine bodies this file
already builds, and none of them had a row in `SHAPE_FOR`. `auditMonsterShapes`
throws at import on a monster with no silhouette, so the whole tree was a build
error. `shapeFor` now falls back to the row's own `family` when `SHAPE_FOR` has
no entry, which is exactly what the programme said that field was for ("each row
names the family it borrows a body from until then"). `SHAPE_FOR` still wins
where it has a row, so no existing monster moved, and a `family` naming
something nothing builds still fails the audit. Revert it and add forty eight
table rows instead if you would rather M2 owned the mapping.
