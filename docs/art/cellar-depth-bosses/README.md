# Old Cellars boss models

Six Blender characters follow the generated [concept sheet](concepts.png). The editable `.blend` files and the game `.glb` exports live in `assets/models/cellars/depth-bosses/`. The materials use packed 512 px albedo maps generated by the retained Blender source. No external texture files are required at runtime.

| Boss | Depth | Body height | Construction |
| --- | --- | --- | --- |
| Morva | 2 | 4.8 m | Six segmented legs, two pincers, 86 skulls, ossuary shell and votive bells |
| Sexton | 3 | 6 m | Hunched hood, skeletal arms, bell yoke and large banded hammer |
| Abbot Cinder | 4 | 7.5 m | Four articulated arms, furnace grate, coals and mitre |
| Ilex | 5 | 9 m | Floating legless shroud, four chained books, parchment strips |
| Voss | 6 | 11 m | Four crawling stone limbs, open cathedral arches, tracery and spires |
| Aster | 7 | 14 m | Crown, ribs, layered burial armor, cape and long sword |

Every model contains `idle`, `walk`, `run`, `attack`, `cast`, `hurt`, `die` and `special` skeletal clips. Gameplay aliases `swing` to `attack` and `air` to `special`. Crawlers fold their limbs on death; the standing characters fall and settle. Vertical ground corrections are baked into the clips. Horizontal travel remains controlled by gameplay.

The build uses material batches with one skinned mesh per material. Runtime validation reads the GLBs in Three.js, decodes the packed PNG pixels, checks skin weights and bounds, then samples every animation. The adapter test exercises deferred load disposal, a failed load, retry, cached construction, picking, animation and GPU bone-texture cleanup.

```sh
/opt/homebrew/opt/python@3.13/bin/python3.13 tools/blender/cellars/mcp_client.py --port 9878 --script tools/blender/cellars/depth-bosses/build.py
node tools/blender/cellars/depth-bosses/validate.mjs --record
node src/game/cellar_depth_boss_model.test.mjs
```

The bridge must be the owned background Blender Lab process on port 9878. The builder leaves the GUI process on 9876 alone. Queue review renders with the room builder before running `render.py`; both use the same Metal GPU. Saved render settings use Cycles, Metal only, MetalRT Auto, GPU OpenImageDenoise and persistent data.

Review artifacts use `<boss-id>-hero.png`; animation pose comparisons use the clip name in the filename. The accompanying build reports and `runtime-validation.json` contain measured mesh counts, payloads, bounds, clip results and export hashes.
